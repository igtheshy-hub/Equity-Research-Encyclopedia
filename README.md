# 专属行业数据库

个人专属的行业数据库。选定一个行业长期追踪，沉淀它的竞争格局、卖方分析师观点、发展趋势与公司经营状况，在数据之上构造自己的行业理解和投资逻辑，并生成自己的报告。行业由使用者自定，各自建库互不绑定。重点能力是数据库本身，所有知识句句标注来源文件和页码（或段落号），越用越厚，可审可查。刻意不走 RAG 路线，知识以 wiki 页面与结构化数据的形式沉淀，而不是问完即弃的检索。

## 追踪什么

- 公司经营状况：raw/filings/ 的财报走四段式摄取（定位 → 抄录 → 勾稽 → 落库），科目原值、多口径指标、管理层引述存 data/fin/<公司>.json，机械计算，句句可回原文
- 卖方观点：研报摄入时编译成一句一条、句尾带锚点的知识条目，归并进公司页与行业页；审校可发现不同研报的矛盾观点
- 行业趋势与竞争格局：选定行业的行业页与产业链上的公司页持续积累，玩家逐页建档
- 自己的理解与投资逻辑：问答中跨页面综合的新知识经确认后以【观点】沉淀在公司页，与卖方数据分层存放；报告按固定结构生成，存 outputs/

观点流结构化、行业时间序列、格局对比视图、投资逻辑工作台是演进方向，见路线图。

## 目录结构

- `raw/` 原始资料层（人工管理，程序只读）：`inbox/` 收件台、`reports/` 卖方研报按行业分目录、`filings/` 上市公司财报按公司分目录、`policies/` 监管政策文件。支持 PDF 与 Word（.docx）
- `wiki/` 维基知识层（程序维护）：`index.md` 总索引、`log.md` 操作日志、`companies/` 公司页、`industries/` 行业页、`concepts/` 概念页、`sources/` 来源摘要页（每份材料一页，摄入时自动生成）
- `schema/CLAUDE.md` 知识库操作规范（格式、锚点语法、各环节规则）
- `outputs/` 产出：用户主动要求生成的报告（对比分析、财务报告等）；审校报告存 `outputs/` 但只在审校页展示
- `data/` 内部状态：摄入清单、逐页/逐段文本缓存、财报结构化数据（`fin/`）、LLM 调用日志、问答会话（conversations.json）

## 快速开始

1. 复制 `.env.example` 为 `.env`，填入模型服务商的 API Key（配置里备了 GLM-5.1 与 DeepSeek-V4.1-Flash 两家，各填各的 key）
2. 体检：`python manage.py selftest`
3. 启动网页：`python manage.py serve`，浏览器打开 http://127.0.0.1:5000

网页流程（推荐）：

1. 首页提问框直接提问，或把文件（PDF / Word .docx）拖进虚线框：自动「取名入库」与「摄入」两条线并行，一份取名入库后立刻开始摄入，取名线不等它、接着处理下一份，页面顶部角标和首页进度条随时可看，切换页面不中断
2. 问答页聊天式提问，答案句句带角标；点角标新标签打开原文对照（PDF 定位到页并高亮，Word 定位到段落），缩放、拖宽都支持
3. 问答产生了跨页面综合的新知识时，任何页面都会弹「提取」窗口，勾选认可的行写入 wiki（日志来源记「会话中提取」）
4. 知识库外的问题自动回退：先搜 raw 文件名给候选，确认后对原文全文深查作答
5. 聊天里提「生成一份对比报告」，产出页看进度和成品
6. 审校页跑四类健康检查，可按最新报告的修复向导勾选动作（摄入遗漏文件、合并碎片页、处理矛盾、标注复核），确认后才动 wiki
7. 日志页看每个条目的档案：类型、标签、摘要、生成/更新时间、来源

等价的命令行流程：`python manage.py sort`（收件台）→ `ingest --all`（可先 `--dry-run` 预览提取）→ `ask "贵州茅台 2024 年营收多少"`（检出新知识时 y/N 确认沉淀）→ `audit`。

## 机制

各环节都由大模型参与、由确定性程序把关：

- 摄入：逐页（PDF）或逐段（Word）提取文本，LLM 编译成一句一条、句尾带锚点的知识条目，程序归并进主题页，并生成来源摘要页。合并只追加不删除，锚点集合只增不减，写盘前程序校验
- 财报摄取：raw/filings/ 的财报不走通用编译，自动分流到四段式流程（定位 → 抄录 → 计算 → 落库），科目原值与多口径指标存 data/fin/<公司>.json，勾稽校验不过整份挂起
- 问答：两步。先凭索引选页（最多 8 页）再用所选页全文作答，附最近几轮上下文支持追问；答案锚点程序逐个校验，违规重试一次后降级标记
- 三级回退：知识库答不了 → 程序搜 raw 文件名与来源摘要给候选（或告知没有候选）→ 用户确认后对候选文件原文（或全库关键词粗筛片段）深查作答，锚点直指 raw 原文
- 会话提取：答案中跨页面综合的新知识先弹窗征求确认，勾选行子集写入，已提取过的行不再出现
- 报告：聊天中识别报告意图即起后台任务，按固定结构（核心结论/分节论述/数据表/风险）生成带锚点长文，存 `outputs/report-*.md`
- 审校：矛盾（附双方原文）、过期、未摄入、孤立四类健康报告 + 结构化 JSON；修复向导按报告列动作清单，人工勾选后执行，全程写日志
- 后台任务：问答、取名、摄入、审校、修复、报告都是服务端线程任务，前端轮询进度，页面随便切
- 模型层：可用模型都在 config.json 的 llm.models 里，一家一份档案（端点、模型名、key 变量名按主机名自动选），llm.default 定默认模型，输出上限与私有参数可整体配也可单模型覆盖；首页提问框左侧的下拉切换本次问答用哪个模型，选择记在浏览器本地，答案头部标注实际使用的模型，每次调用都记进 data/llm_log.jsonl；调用兼容 Anthropic Messages 与 OpenAI 两种格式，思考模式默认关闭，长输入不会因思考耗时顶爆读超时

## 路线图

- 分析师观点流：研报摄入时抽取券商、日期、评级、目标价、核心逻辑为结构化记录，观点矩阵与时间线视图，目标价分歧由程序检测
- 行业时间序列：行业级指标 × 时期的结构化数据文件，与财报 periods 同构
- 竞争格局对比：公司 × 指标的对比表与份额视图，吃 data/fin/ 已有底子
- 投资逻辑工作台：假设—证据—验证状态的个人框架，追踪自己论点的证实与证伪

详细规范见 `schema/CLAUDE.md`。

## 已知限制

扫描版 PDF 无文本层会被拒绝（无 OCR）；旧版 .doc 不支持，请先另存为 .docx；双栏排版与表格的文本流可能乱序，靠点角标对照原文人工抽查兜底；选页只看索引摘要（无向量检索，刻意取舍），深埋细节可能漏选；矛盾检测是待人工复核清单而非结论；同名不同版本的文件会让旧锚点指向新内容（文件名带日期规避）；Flask 本地单机无鉴权；PDF 文本层高亮对无文本层的扫描件无效（定位到页仍可用）。
