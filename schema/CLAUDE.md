# 行业知识库操作规范

## 项目概述

本项目为行业研究的 LLM Wiki 知识库。raw/ 存放原始资料（人工管理，智能体只读），wiki/ 存放编译后的知识页面（智能体维护），outputs/ 存放查询产出。

本文件是操作细则总册：根 CLAUDE.md 定大方向（问答规则、写入纪律、流水线分工），会话工作流在 .claude/skills/（kb-ask 问答、finstmt-qa 财报问答、finstmt-ingest 财报摄取、company-report / industry-report 研报框架），程序实现在 src/。

## Wiki 页面格式

每个 wiki 页面必须包含以下 YAML frontmatter：

```yaml
---
title: 条目名称（如"宁德时代"）
type: company | industry | concept | source
sources:
  - raw/reports/new-energy/2026Q1-solar-outlook.pdf
updated: 2026-04-20
---
```

正文使用 Markdown 格式，关键数据标注来源文件路径。页面之间用 [[wikilink]] 语法互相引用。

### 格式细则（程序补充）

锚点语法：正文关键数据句尾用 `[[文件名.pdf#p页码]]` 或 `[[文件名.docx#para段落号]]` 标注，如 `[[中信证券_贵州茅台_20240501.pdf#p5]]`。Word 无固定页码，按文档顺序的块序号（段落/表格）定位，`paraN` 的 N 与网页对照视图里显示的块号一致。锚点只写文件名不写路径，文件名必须全库唯一；frontmatter 的 sources 记录完整的 raw/ 相对路径。文件名不得含 `[ ] # |` 与空格。

正文一行一条知识，句尾锚点。页内分节用固定节枚举：公司页「公司概况 / 行业格局 / 经营与财务 / 盈利预测 / 估值 / 分析观点 / 风险提示 / 其他」；行业页把首节换成「行业概况」，其余同公司页；概念页「定义与口径 / 方法要点 / 政策背景 / 应用示例 / 其他」；来源摘要页不强制分节。

frontmatter 除必填的 title / type / sources / updated 外，可加 aliases（别名，匹配用）、summary（一句话摘要，进总索引）、history（更新历史，每次摄入追加一行）。type 决定页面所在子目录：company → wiki/companies/，industry → wiki/industries/，concept → wiki/concepts/，source → wiki/sources/。

页面间互引用用 `[[页面标题]]`，只能指向已存在的页面；跨类型引用也算有效入链。

## 收件台规则

- 新文件先进 raw/inbox/（网页上传或人工复制），支持 PDF 与 Word（.docx；旧 .doc 拒收并提示另存为 .docx）
- 智能体读取每份文件开头若干页（PDF）或若干段（Word）文字，判断类型（卖方研报 / 公司财报 / 监管政策）、主题、出具方与日期，生成规范文件名（如 中信证券_白酒行业研报_20260312.pdf），文件名只用安全字符，不含空格与 [ ] # |
- 程序校验文件名合法性与全库唯一性（重名自动加序号后缀），把文件移入对应目录：研报 → raw/reports/<行业>/，财报 → raw/filings/<公司>/，政策 → raw/policies/
- 落盘前按 SHA256 查重：下载暂存、归名移动、快照生成、摄入清理四道闸都按内容判重，同内容文件只保留一份，重复件直接删除，不生成 `-2/-3` 副本
- 网页端上传后自动链式执行：取名入库任务完成即自动起摄入任务，两者独立进度；命令行 `python manage.py sort` 只做取名
- 收件台只移动 inbox/ 内的文件；已归入 raw/ 正式目录的文件智能体只读（inbox 是「raw/ 人工管理」的唯一例外区）
- 取数快照是例外：`python -m src.snapshot` 生成的 DOCX 不进收件台（三类判定会把快照拼成「研报」），按 `<机构>_<主题>快照_<取数日期>.docx` 直接写 raw/reports/数据快照/，落盘后直接摄入（unit=para，锚点 paraN）

## Ingest 规则

- 读取 raw/ 中的新文档，提取核心观点、数据和结论
- 研报与政策的编译按固定维度清单提炼，命中的维度归入对应节：评级与目标价、盈利预测数字→盈利预测；估值方法与假设→估值；市场规模、量价、份额格局→行业格局；业务进展与财务→经营与财务；政策法规与口径定义→概念页；风险因素→风险提示。材料没写的维度跳过，判断类观点仍不在摄入层产出
- 更新或创建对应的 wiki 页面（公司页、行业页、概念页）
- 新建页面必须填写完整的 YAML frontmatter
- 更新 wiki/index.md，为新页面添加索引条目（含一句话摘要）
- 在 wiki/log.md 记录本次摄入操作：日期、源文件、影响的 wiki 页面列表

### 程序保证（补充）

- 幂等：同一文件按 SHA256 判断，重复摄入直接跳过；raw 中与已摄入文件同内容的副本在摄入前自动删除
- 扫描版检测：有效页平均字符数过低（无文本层）时拒绝摄入并说明原因
- 合并只追加：并入已有页时在对应节末尾逐行追加，旧条目不删改；写盘前程序断言旧页锚点集合是新页子集（只增不减）
- 锚点真实性：所有锚点的文件名必须在已摄入清单内、页码不得超过该文件实际页数
- 来源摘要页：每份材料摄入时在 wiki/sources/ 自动生成一页（type: source，文件名作页名），正文记录该材料的主题、核心结论、贡献到哪些主题页，不用打开 PDF 即可追溯
- 超过 40 页的长报告分段编译后合并条目

### ingest 后人工核对（会话层）

- 合并判定按标题各建新页，同义标题（如乘用车市场/乘用车整体市场/乘用车总体市场/中国乘用车市场）会拆成平行页。每次 ingest 跑完读 wiki/index.md 核对新页
- 发现近义重复页先向用户提案合并方案，确认后合并：只追加不删除，旧页名留进 aliases，修正来源页 wikilink，重建索引
- 抽查新页条目有没有名称错字（实例：奇瑞被编译成奇奇）与数值错位

### 财报摄取（专用流程）

- raw/filings/ 的财报不走通用编译提示词，ingest_one 自动分流到 src/filing.py 四段式流程（定位 → 抄录 → 计算 → 落库），完整规则见 .claude/skills/finstmt-ingest/SKILL.md
- 公司页「经营与财务」节追加结构化行：【数据】报告期 合并 科目 = 数值元 [[锚点]]（报表原值）、【指标】报告期 指标名(口径) = 数值 [[锚点]]（代码机械计算的派生值，多口径并存）、【管理层】「原话」——语境 [[锚点]]、【数据】报告期 目标 数据名（口径） = 数值 单位 [[锚点]]（带目标清单摄入时按清单补抄的字典外数据，仅当次摄入产生）；判断类内容一律不在摄取层产出
- 勾稽校验（R1—R4，容差 config.ingest.filing_check_tol）任一失败整份挂起：不入 manifest、不上 wiki，错误清单打印交人工
- 结构化存储 data/fin/<公司slug>.json：periods 按报告期（如 2025FY）存科目原值、母公司口径、管理层引述与派生指标；后续报告期的同比/单季/TTM/平均口径从该文件取上年数据，缺则指标进缺失清单不阻塞
- 科目名经 schema/filing_items.json 别名表归一到规范名，字典外科目保留原名并在 source 页备注；source 页材料信息含审计意见与缺失清单
- LLM 只做定位与抄录（task=filing，温度 0），勾稽与指标全部由 src/fin_calc.py 代码计算
- 研报管线补定期报告时把本次勾选的数据缺口作为目标清单随取数带进财报摄入（industry_report._gap_targets → fetcher.run_fetch(targets=...) → ingest_one → ingest_filing），标准科目字典之外的目标数据也按【数据】目标行入库；首页关注点同样并入目标清单

## Query 规则

- 加载 wiki 页面，用 frontmatter 的 summary 与正文拼紧凑索引定位相关页面；wiki/index.md 只供人浏览与导出，检索不解析它
- 综合多个 wiki 页面回答问题，标注信息来源
- 如果综合答案构成新知识，写入 wiki/ 新页面并更新 wiki/log.md；研究报告等产出物写入 outputs/
- 回答中引用的数据必须标注 wiki 页面路径和原始来源
- 会话内问答（Claude Code）走根 CLAUDE.md 的问答规则与 .claude/skills/kb-ask/SKILL.md，写入受 .claude/hooks/page_check.py 钩子校验；与下方程序管道行为一致（库里没有的明说没有，不用模型自身知识补答）

### 程序保证（网页与命令行共用同一管道）

- 两步问答：第一步凭索引选页（最多 8 页，config.json 的 ask.max_pages），第二步只用所选页全文作答；选页与作答都附最近 N 轮问答摘要（ask.history_turns，默认 4），支持追问
- 意图判别：每条提问先判定普通问答还是报告请求，报告请求再分行业研报、公司研报与其余报告。行业研报与公司研报都走 src/industry_report.py 状态机（job 带 kind 区分；公司研报按 .claude/skills/company-report 的八节权威框架定大纲，另取库内既有研报对该公司或其行业的覆盖章节，取料页强制含该公司页面；最近一年内的年报、半年报、季报逐类列为必选缺口，缺哪类补哪类，未补齐不能成文；港股季报不强制，缺季报不阻断成文。两类研报的样板都取新财富该行业组前 3 券商研报，每家 1 份、至少 3 份，库内优先，缺的走慧博免登录榜单加东财下载，某家在东财缺货按名次顺延，仍取不满时放宽为综合最优研报先成文并在审校记录注明前 3 占比与补齐方法）（选样板→大纲确认→缺口补料→分节成文→图表→审稿→转 Word→A-F 候选沉淀，状态存 data/report_jobs/），其余报告走内置 src/report.py 按固定四段结构生成 outputs/report-<日期>-<标题>.md；两条路的进度都在任务卡展示。命令行 ask 的行业研报请求落内置四段式（无确认关卡）
- 三级回退：选页为空 → 程序把 raw/ 全部文件名 + 来源摘要喂给模型挑候选（最多 5 个），按固定话术询问用户是否进一步查询（无候选与有候选话术不同）；用户确认 → 后台深查：指定文件用其全部页/段文本，全库模式先按关键词粗筛取片段，再由模型作答，锚点直指 raw 原文
- 深查锚点校验放宽为「文件存在于 raw/ 且序号不超过提取单元数」（manifest ∪ 提取缓存）；深查答案不自动写 wiki
- 答案锚点只能引用所选页面中出现过的来源文件；程序逐锚点校验，违规重试一次，仍违规在答案上方标记警告
- 页面没有的信息必须回答「知识库中没有该信息」，禁止用模型自身知识补全
- 会话提取：答案中跨页面综合的新知识由模型提案（只算不写），网页端弹窗征求确认、可勾选行子集，写入时 history 记「会话中提取」/「会话中提取新建」，已提取过的行不再重复呈现；命令行 y/N 确认
- 财报分析注入：意图判别同时输出领域（finstmt/general），涉及报表数据、比率、盈利、现金流、偿债、周转、地雷、审计意见等的问题判为 finstmt，在问答、深查、报告三处提示词注入财报分析纪律（先盘数据再判断、指标必带口径与报告期、阈值注明张明辉出处并提示 A 股适用限度、地雷六特征逐项过数、缺数明说、结论分层），流程见 .claude/skills/finstmt-qa/SKILL.md
- 【观点】沉淀：财报分析判断属主观观点，只能经会话提取产生（模型提案时以【观点】前缀标行，格式【观点】报告期 判断句），用户确认后写入公司页「分析观点」节；摄取层永不产出观点行
- 新知识回流的条目同样必须带 raw 来源锚点，无锚点的新知识不写入 wiki
- 会话持久化：问答会话与消息流存 data/conversations.json，重启不丢

### 报告成稿沉淀（A—F 分类，会话与网页共用 src/report_distill.py）

报告成稿后先给正文无锚点句逐句分类，A/D/E 三类进候选请用户逐条勾选，B 类补锚点或改写成 A 类，C/F 不写入 wiki：

- A 综合判断：跨材料综合、任何单页都没明说的判断 → 勾选后以【个人观点】行写入
- B 复述漏锚：单份材料已有、只是缺锚点 → 补锚点即可
- C 口径方法：口径与方法的讲解 → 不写入
- D 前瞻预测：对未来的判断 → 必须写清预测条件与预测日期
- E 推导计算：用库内数据算出的新数值 → 必须经代码复核并挂锚点，确认后按普通数据行写入，句尾注明计算口径
- F 行文框架：成文结构语句 → 不写入

写入格式：【观点】报告期 判断句（会话提取产生，进公司页「分析观点」节）；【个人观点】判断句 [[锚点]]（个人研报观点，日期，报告文件名）（报告成稿勾选产生，进行业页或公司页「分析观点」节）。两种行句尾都必须带支撑它的库内锚点，前瞻判断须在句中写明预测条件与日期。

## 来源优先级

- 公司财务数据：财报（年报、半年报、季报）> 公告/招股书 > 券商研报 > 其他材料
- 同一公司财务指标冲突时，以最新报告期的财报为准；研报数字只能作对照，并写明差异与各自报告期
- 行业总量数据不套此序，统计局、行业协会、海关等一手来源优先于研报预测
- 审校、问答、研报成文三处共用 src/source_priority.py 的判定；页面头标注来源类型，矛盾项给出保留方
- 财报摄取仍是公司财务数据的唯一结构化渠道，结构化字段与指标以 data/fin 为准

## Lint 规则

- 检查 wiki 页面间是否存在矛盾观点（如不同研报对同一公司的相反评级），按来源优先级给出保留方
- 标记超过 90 天未更新的页面为待审查
- 发现 raw/ 中有文档未被摄入时，输出提醒
- 检查孤立页面（无任何其他页面引用的条目）
- 输出格式：按严重程度分为"矛盾""过期""未摄入""孤立"四类，每类列出具体页面

### 程序补充

- 过期阈值 90 天可在 config.json 调整（audit.stale_days）
- 未摄入 = raw/ 中存在但不在 data/manifest.json 的文件（PDF 与 docx 同口径）
- 孤立按 [[wikilink]] 引用图计算；另将单一来源且条目数过少的页面、标题互为包含的两页列为合并建议
- 矛盾检测区分「事实矛盾」与「时点差异」（不同日期报告的预测更新属正常更新，单列不报警）；矛盾项附双方原文与锚点
- 观点老化：【观点】行依据的报告期早于页内最新【数据】报告期时列入「过期」类待复核（观点不自动删除，新旧并存由审校裁决）
- 审校报告存 outputs/audit-<时间戳>.md（只在审校页展示），同时落盘结构化 data/audit-<时间戳>.json；网页端「按最新报告修改 wiki」向导按 JSON 列出可执行动作（摄入遗漏文件 / 合并方向选择 / 矛盾保留方选择 / 过期标注复核），人工勾选确认后由修复任务执行，全程写 wiki/log.md；其中删行类操作属人工决策，明确绕过「锚点只增不减」断言并留痕

## 任务与网页架构（程序补充）

- 所有耗时操作（问答、取名入库、摄入、审校、修复、报告、取数、删除）跑在服务端后台线程，状态存进程内任务注册表（src/tasks.py），前端轮询 /api/tasks 取进度；任务在用户点掉完成卡片前保留，切换页面不中断
- 取名入库 / 摄入 / 审校 / 修复 / 报告 / 取数按类型互斥排队；问答不限并发
- 研报管线跨阶段使用多个 report 任务，阶段产物与确认状态落 data/report_jobs/<id>.json，服务重启后可按 job 状态续跑
- 网页路由：/ 首页（提问框 + 上传区 + 进度）、/kb 知识库、/ask 问答（支持双栏会话分屏）、/report 研报管线（大纲确认、缺口勾选、候选沉淀）、/fetch 主动取数、/audit 审校、/log 日志（按 wiki 条目展示元数据）、/viewer 原文对照（PDF.js 渲染 PDF：定位页 + 文本层高亮 + 缩放；docx 转 HTML：定位段落 + 高亮）

## 命令用法

```
python manage.py selftest              # 体检：依赖、API 连通、库外问答回退、全库校验
python manage.py sort                  # 收件台：归类 raw/inbox/ 中的新文件（PDF 与 .docx）
python manage.py ingest [--all | --file 路径] [--dry-run]
python manage.py ask "问题"            # 检出新知识时 y/N 确认沉淀；报告请求自动转生成
python manage.py audit
python manage.py validate
python manage.py serve                 # 本地网页 http://127.0.0.1:5000
python -m src.snapshot spec.json       # 网页/API 数据落 DOCX 快照进 raw/reports/数据快照/
```
