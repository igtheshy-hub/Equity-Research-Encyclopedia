# 投研知识库操作规范

## 项目概述

本项目为投研团队的 LLM Wiki 知识库。raw/ 存放原始资料（人工管理，智能体只读），wiki/ 存放编译后的知识页面（智能体维护），outputs/ 存放查询产出。

## Wiki 页面格式

每个 wiki 页面必须包含以下 YAML frontmatter：

```yaml
---
title: 条目名称（如"宁德时代"）
type: company | industry | concept | source
sources:
  - raw/reports/new-energy/2026Q1-solar-outlook.pdf
updated: 2026-04-20
---
```

正文使用 Markdown 格式，关键数据标注来源文件路径。页面之间用 [[wikilink]] 语法互相引用。

### 格式细则（程序补充）

锚点语法：正文关键数据句尾用 `[[文件名.pdf#p页码]]` 或 `[[文件名.docx#para段落号]]` 标注，如 `[[中信证券_贵州茅台_20240501.pdf#p5]]`。Word 无固定页码，按文档顺序的块序号（段落/表格）定位，`paraN` 的 N 与网页对照视图里显示的块号一致。锚点只写文件名不写路径，文件名必须全库唯一；frontmatter 的 sources 记录完整的 raw/ 相对路径。文件名不得含 `[ ] # |` 与空格。

正文一行一条知识，句尾锚点。页内分节用固定节枚举：公司页「公司概况 / 行业格局 / 经营与财务 / 分析观点 / 盈利预测 / 估值 / 风险提示 / 其他」；行业页把首节换成「行业概况」，其余同公司页；概念页「定义与口径 / 方法要点 / 政策背景 / 应用示例 / 其他」；来源摘要页不强制分节。

frontmatter 除必填的 title / type / sources / updated 外，可加 aliases（别名，匹配用）、summary（一句话摘要，进总索引）、history（更新历史，每次摄入追加一行）、focus（用户关注点）、focus_hits（命中关注点的原文片段，最多 50 条）、needs_review（删除原文件后有内容失去锚点时置 true）、review_reason（需复核原因）。`needs_review: true` 的页面允许 sources 暂时为空、允许【数据】/【指标】行暂时无锚点（这两类豁免只在页面标记期间生效），页面顶部会显示「需复核」提示，审校报告单列「需复核」并在修复向导里提供确认动作；人工确认后清除这两个字段，逐行锚点检查恢复。type 决定页面所在子目录：company → wiki/companies/，industry → wiki/industries/，concept → wiki/concepts/，source → wiki/sources/。

页面间互引用用 `[[页面标题]]`，只能指向已存在的页面；跨类型引用也算有效入链。

## 收件台规则

- 新文件先进 raw/inbox/（网页上传或人工复制），支持 PDF 与 Word（.docx；旧 .doc 拒收并提示另存为 .docx）
- 智能体读取每份文件开头若干页（PDF）或若干段（Word）文字，判断类型（卖方研报 / 公司财报 / 监管政策）、主题、出具方与日期，生成规范文件名（如 中信证券_白酒行业研报_20260312.pdf），文件名只用安全字符，不含空格与 [ ] # |
- 程序校验文件名合法性与全库唯一性（整个 raw/ 范围内重名自动加序号后缀；连去掉扩展名的 stem 也要求唯一，避免来源页与提取缓存相撞），把文件移入对应目录：研报 → raw/reports/<行业>/，财报 → raw/filings/<公司>/，政策 → raw/policies/
- 历史遗留的同名多份文件不会被静默挑一份：查看、摄入、删除都会报错并列出全部路径，要求先改名或移走重复文件；原文件页与全库校验也会提示
- 网页端上传后自动链式执行：取名入库任务完成即自动起摄入任务，两者独立进度；命令行 `python manage.py sort` 只做取名
- 收件台只移动 inbox/ 内的文件；已归入 raw/ 正式目录的文件智能体只读（inbox 是「raw/ 人工管理」的唯一例外区）

## Ingest 规则

- 读取 raw/ 中的新文档，提取核心观点、数据和结论
- 更新或创建对应的 wiki 页面（公司页、行业页、概念页）
- 新建页面必须填写完整的 YAML frontmatter
- 更新 wiki/index.md，为新页面添加索引条目（含一句话摘要）
- 在 wiki/log.md 记录本次摄入操作：日期、源文件、影响的 wiki 页面列表

### 程序保证（补充）

- 幂等：同一文件按 SHA256 判断，重复摄入直接跳过
- 扫描版检测：有效页平均字符数过低（无文本层）时拒绝摄入并说明原因
- 合并只追加：并入已有页时在对应节末尾逐行追加，旧条目不删改；写盘前程序断言旧页锚点集合是新页子集（只增不减）
- 锚点真实性：所有锚点的文件名必须在已摄入清单内、页码不得超过该文件实际页数
- 来源摘要页：每份材料摄入时在 wiki/sources/ 自动生成一页（type: source，文件名作页名），正文记录该材料的主题、核心结论、贡献到哪些主题页，不用打开 PDF 即可追溯
- 长报告按 config.json 的 ingest.compile_chunk_pages（默认 20）分段编译后合并条目，不再写死 40 页
- 摄入任务可取消、有总超时（ingest.task_timeout_s，默认 2 小时）；取消后在下一个可中断点停止，已摄入的部分照常落盘并重建索引

### 财报摄取（专用流程）

- raw/filings/ 的财报不走通用编译提示词，ingest_one 自动分流到 src/filing.py 四段式流程（定位 → 抄录 → 计算 → 落库），完整规则见 schema/财报摄取-skill.md
- 公司页「经营与财务」节追加三类结构化行：【数据】报告期 合并 科目 = 数值元 [[锚点]]（报表原值）、【指标】报告期 指标名(口径) = 数值 [[锚点]]（代码机械计算的派生值，多口径并存）、【管理层】「原话」——语境 [[锚点]]；判断类内容一律不在摄取层产出
- 勾稽校验（R1—R3，容差 config.ingest.filing_check_tol）任一失败整份挂起：不入 manifest、不上 wiki，错误清单打印交人工
- 结构化存储 data/fin/<公司slug>.json：periods 按报告期（如 2025FY）存科目原值、母公司口径、管理层引述与派生指标；每个科目存 `{v, a, unit, statement, listed}`，unit 区分「元 / % / 元/股 / 股」等，金额统一换算成元，百分数保留披露的百分点原值（15.31 表示 15.31%），每股收益不按万元缩放；后续报告期的同比/单季/TTM/平均口径从该文件取上年数据，缺则指标进缺失清单不阻塞
- 展示按单位走：金额「元」、ROE/毛利率等比率「%」、EPS「元/股」（保留四位，不抹成整数）、DSO/DIO/DPO/CCC「天」；ROE(加权披露) 只按披露单位换算（unit 为 % 才除以 100），不再用 abs>1.5 猜
- 每条【数据】/【指标】行必须带锚点；CCC 的锚点取 DSO/DIO/DPO 三个分项来源科目的并集，不能为空
- 科目名经 schema/filing_items.json 别名表归一到规范名，字典外科目保留原名并在 source 页备注；source 页材料信息含审计意见与缺失清单
- LLM 只做定位与抄录（task=filing，温度 0），勾稽与指标全部由 src/fin_calc.py 代码计算

## Query 规则

- 先读取 wiki/index.md 定位相关页面
- 综合多个 wiki 页面回答问题，标注信息来源
- 如果综合答案构成新知识，写入 wiki/ 新页面并更新 wiki/log.md；研究报告等产出物写入 outputs/
- 回答中引用的数据必须标注 wiki 页面路径和原始来源

### 程序保证（网页与命令行共用同一管道）

- 两步问答：第一步凭索引选页（最多 8 页，config.json 的 ask.max_pages），第二步只用所选页全文作答；选页与作答都附最近 N 轮问答摘要（ask.history_turns，默认 4），支持追问
- 意图判别：每条提问先判定普通问答还是报告请求；报告请求起后台任务，按固定结构生成 outputs/report-<日期>-<标题>.md，进度在产出页展示
- 三级回退：选页为空 → 程序把 raw/ 全部文件名 + 来源摘要喂给模型挑候选（最多 5 个），按固定话术询问用户是否进一步查询（无候选与有候选话术不同）；用户确认 → 后台深查：指定文件用其全部页/段文本，全库模式先按关键词粗筛取片段，再由模型作答，锚点直指 raw 原文
- 深查锚点校验放宽为「文件存在于 raw/ 且序号不超过提取单元数」（manifest ∪ 提取缓存）；深查答案不自动写 wiki
- 答案锚点只能引用所选页面中出现过的来源文件；程序逐锚点校验，违规重试一次，仍违规在答案上方标记警告
- 页面没有的信息必须回答「知识库中没有该信息」，禁止用模型自身知识补全
- 会话提取：答案中跨页面综合的新知识由模型提案（只算不写），网页端弹窗征求确认、可勾选行子集，写入时 history 记「会话中提取」/「会话中提取新建」，已提取过的行不再重复呈现；命令行 y/N 确认
- 提案提醒语义：GET /api/proposals/pending 是只读查询，刷新或切页不会把提案标记为已提醒；「稍后处理」只推迟 24 小时（proposal_snoozed_until），「不再提醒」才写 proposal_dismissed=true；关闭弹窗既不推迟也不丢弃，下次仍会出现
- 财报分析注入：意图判别同时输出领域（finstmt/general），涉及报表数据、比率、盈利、现金流、偿债、周转、地雷、审计意见等的问题判为 finstmt，在问答、深查、报告三处提示词注入财报分析纪律（先盘数据再判断、指标必带口径与报告期、阈值注明张明辉出处并提示 A 股适用限度、地雷六特征逐项过数、缺数明说、结论分层），流程见 schema/财报问答-skill.md
- 【观点】沉淀：财报分析判断属主观观点，只能经会话提取产生（模型提案时以【观点】前缀标行，格式【观点】报告期 判断句），用户确认后写入公司页「分析观点」节；摄取层永不产出观点行
- 新知识回流的条目同样必须带 raw 来源锚点，无锚点的新知识不写入 wiki
- 会话持久化：问答会话与消息流存 data/conversations.json，重启不丢

## Lint 规则

- 检查 wiki 页面间是否存在矛盾观点（如不同研报对同一公司的相反评级）
- 标记超过 90 天未更新的页面为待审查
- 发现 raw/ 中有文档未被摄入时，输出提醒
- 检查孤立页面（无任何其他页面引用的条目）
- 输出格式：按严重程度分为"矛盾""过期""未摄入""孤立"四类，每类列出具体页面

### 程序补充

- 过期阈值 90 天可在 config.json 调整（audit.stale_days）
- 未摄入 = raw/ 中存在但不在 data/manifest.json 的文件（PDF 与 docx 同口径）
- 孤立按 [[wikilink]] 引用图计算；另将单一来源且条目数过少的页面、标题互为包含的两页列为合并建议
- 矛盾检测区分「事实矛盾」与「时点差异」（不同日期报告的预测更新属正常更新，单列不报警）；矛盾项附双方原文与锚点
- 观点老化：【观点】行依据的报告期早于页内最新【数据】报告期时列入「过期」类待复核（观点不自动删除，新旧并存由审校裁决）
- 审校报告存 outputs/audit-<时间戳>.md（只在审校页展示），同时落盘结构化 data/audit-<时间戳>.json；网页端「按最新报告修改 wiki」向导按 JSON 列出可执行动作（摄入遗漏文件 / 合并方向选择 / 矛盾保留方选择 / 过期标注复核），人工勾选确认后由修复任务执行，全程写 wiki/log.md；其中删行类操作属人工决策，明确绕过「锚点只增不减」断言并留痕
- 合并页面后，程序会把其他页指向被删页标题的 `[[双链]]` 降级成纯文字，避免校验一直报「链接指向不存在页面」
- 删除原文件后保留的无锚点内容会在页面置 `needs_review: true`，审校单列「需复核」；修复向导勾选确认后清除标记，页面恢复逐行锚点校验
- 格式损坏的页面（缺 front matter、YAML 写坏）在审校里单列「格式损坏」，其余页面照常检查；网页打开该页显示中文错误说明，不影响整站
- 摄入任务的总超时读 `config.json` 的 `ingest.task_timeout_s`（默认 7200 秒），超时与手动取消都在下一个可中断点停止

## 任务与网页架构（程序补充）

- 所有耗时操作（问答、取名入库、摄入、审校、修复、报告、删除）跑在服务端后台线程，状态存进程内任务注册表（src/tasks.py），前端轮询 /api/tasks 取进度；完成卡片点掉后移除，注册表最多保留 200 条，超出自动清理最老的已结束任务
- 取名入库 / 摄入 / 审校 / 修复 / 报告按类型互斥排队；问答不限并发。等待中的任务也会显示；运行中与排队中的任务可点「取消」，后台循环在下一个可中断点停止；摄入链另设总超时
- 模型选择：网页下拉选中的模型随请求传给后台任务，取名、摄入、审校、修复、问答全部生效；config.json 的 llm.default 可写 "auto"，按 .env 里配了 key 的模型顺序自动选，协作者不必改配置文件
- 网页路由：/ 首页（提问框 + 上传区 + 进度）、/kb 知识库、/ask 问答（支持双栏会话分屏）、/files 原文件（列表、重复名警告、批量删除）、/audit 审校、/outputs 产出、/export Excel 导出（科目 / 指标 / 条目 / 来源四张表，需 openpyxl）、/log 日志（按 wiki 条目展示元数据）、/viewer 原文对照（PDF.js 渲染 PDF：定位页 + 文本层高亮 + 缩放；docx 转 HTML：定位段落 + 高亮）
- 数据隔离：wiki/、data/、outputs/、raw/ 都进 .gitignore，克隆后首次启动自动创建空目录与 index/log。每人的知识库、会话、LLM 日志、材料清单都只在自己机器上；data/conversations.json 损坏时先备份成 conversations.corrupt-<时间>.json 再以空会话启动，网页启动自检会提示

## 命令用法

```
python -m pip install -r requirements.txt   # 首次安装依赖（含导出用的 openpyxl）
python manage.py selftest              # 体检：依赖、API 连通、库外问答回退、全库校验
python manage.py sort                  # 收件台：归类 raw/inbox/ 中的新文件（PDF 与 .docx）
python manage.py ingest [--all | --file 路径] [--dry-run]
python manage.py ask "问题"            # 检出新知识时 y/N 确认沉淀；报告请求自动转生成
python manage.py audit
python manage.py validate
python manage.py serve                 # 本地网页 http://127.0.0.1:5000
```
