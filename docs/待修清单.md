### 60. 公网部署下自动救火与热重载的边界（2026-11-06 记）

- 隐患：自动救火＝任何任务进 error 就放出能改代码、能跑命令的代理子进程，公网多用户下等于用户提交内容可间接在服务器上改代码（热重载还让改动几秒内直接生效），上公网须关自动救火或加权限门槛；热重载是单进程开发服务器特性，换 waitress/gunicorn 多 worker 后不适用，救火员改代码的生效路径要改走部署流程
- 空窗：本地直连无 nginx，页面轮询每 2.5 秒一次且 fetch 失败静默吞掉，换 worker 的 1-2 秒空窗只表现为少刷新一格；挂 nginx 后单实例重启会在空窗回 502，标准解法是冗余（多 worker，一个重启另一个接着服务，即 gunicorn 优雅重启）或监听 socket 交接
- 本次只做本地热重载与启动清扫，公网部署那一摊另行设计
