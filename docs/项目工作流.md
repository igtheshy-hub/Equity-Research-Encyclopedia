## 1. 一页看懂

整个系统是一条从原始材料到可引用知识的流水线，外加几条下游出口。

```
raw/inbox/                         网页/API 取数
   │  ① 取名线                         │  快照 src/snapshot
   ▼                                  ▼
raw/reports/、raw/filings/、raw/policies/、raw/reports/数据快照/
   │  ② 提取：PDF 逐页、DOCX 逐块，文本缓存到 data/extracts/
   ▼
data/extracts/*.units.json
   │  ③ 摄入：研报/政策走通用编译，财报走四段式专用流程
   ├──────────────────────────────┐
   ▼                              ▼
wiki/*.md + wiki/sources/*     data/fin/<公司>.json
   │
   ├── ④ 问答 ask：选页 → 作答 → 锚点校验 → 会话提取
   ├── ⑤ 审校 audit：矛盾/过期/未摄入/孤立 → 修复向导
   ├── ⑥ 报告：行业研报与公司研报走 industry_report 状态机，其余走 report.generate
   ├── ⑦ 取数 fetcher：免登录源 → 原件或快照 → 自动摄入
   ├── ⑧ 导出 excel_export：科目/指标/条目/来源四张表
   └── ⑨ 删除 purge：按材料清理全链路痕迹
```

一次完整循环可以压成六步：

1. 材料进入 `raw/inbox/`，网页上传或人工复制；也可由取数页直接落原件或快照。
2. 取名线把文件改成规范名，移入 `raw/reports|filings|policies/`；快照直接进 `raw/reports/数据快照/`，不走收件台。
3. 摄入线提取文本。研报和政策编译成一句一条、句尾带锚点的知识行；财报走定位、抄录、勾稽、落库四段。
4. 知识行并入主题页，同时生成一份来源摘要页；财报另有 `data/fin/` 结构化数据。
5. 提问时先凭索引选页（提示词上限 8 页），再只用选中的页面作答；每条数据都要带锚点。
6. 答案里跨页面综合出的新知识，经用户勾选后写入 wiki；审校、报告、取数、导出、删除都建立在这套数据之上。

### 三条硬约束

整个项目可以看成对这三条规则的反复实现。

**第一，知识行必须能回到原文。** 正文里的关键数据句尾带 `[[文件名.pdf#p页码]]` 或 `[[文件名.docx#para段落号]]`。锚点只写文件名，文件名全库唯一。摄入时程序逐条检查锚点是否指向本文件、单元类型是否正确、序号是否越界，不合格的行直接丢弃。

**第二，合并只追加，不删改。** 新知识并入已有页时，旧行原样保留；写盘前程序断言旧页的锚点集合是新页锚点集合的子集。这个断言拦住了模型在合并时顺手改写旧内容的情况。只有审校修复里的人工决策可以明确绕过它，并写进 history 与操作日志。

**第三，大模型只做语言类工作，程序做确定性把关。** LLM 负责分类、编译、定位、抄录、选页、作答、审校提案；文件名合法性、锚点真实性、勾稽等式、指标公式、任务互斥、清单一致性都由代码控制。判断类内容不进入摄入层，只能经问答和用户确认后以【观点】沉淀。

这三条决定了后面所有细节的形状。

## 2. 项目定位与设计取舍

这是一个本地单机、单用户的行业研究知识库。Flask 只监听 `127.0.0.1:5000`，没有登录与权限系统；数据全部落在工作目录里，`raw/` 与 `data/extracts/` 被 `.gitignore` 排除，原因是原文有版权、提取文本含全文。

它刻意不走 RAG 路线。常见 RAG 是切块、向量化、按相似度召回，再把片段塞给模型；这个项目把知识编译成 wiki 页面和结构化财报数据，检索时先看总索引选页，再读整页。这样做的代价是选页只看索引摘要，深埋细节可能漏选；收益是知识会沉淀、可审校、可增量维护，而不是问完即弃。

知识分两层存放。`wiki/` 是给人看的、可引用的知识层，一行一条，句尾带锚点；`data/fin/` 是给程序算的财务数据层，科目原值、母公司口径、管理层引述、派生指标分开存。两层之间通过公司页的【数据】【指标】【管理层】行对应。原始材料 `raw/` 是第三层，只负责保存原件和提供锚点目标。

这个项目按“一个行业长期追踪”设计。索引是一张紧凑的文本表，页数在几十到几百页时选页效果最好；行业数量继续增长后，索引会变长，选页准确率会下降，这是当前架构的已知边界。

## 3. 分层架构

| 层 | 组成 | 职责 |
|---|---|---|
| 入口层 | `manage.py` 命令行、Flask 网页 | 接收用户操作，命令行与网页共用同一套业务函数 |
| 编排层 | `src/tasks.py`、`src/sessions.py`、`src/web/api.py` 的 `_pipeline` | 后台线程、任务状态、会话持久化、两条线并行 |
| 业务层 | `classify`、`ingest`、`filing`、`ask`、`audit`、`fix`、`report`、`industry_report`、`report_distill`、`fetcher`、`purge`、`excel_export` | 每条业务链路的具体步骤 |
| 基础层 | `llm`、`pdf_extract`、`wiki`、`wiki_check`、`validate`、`config`、`fin_calc`、`snapshot`、`charts`、`convert_report`、`docx_html` | 模型调用、文本提取、页面读写与校验、配置、财务计算、快照、图表、转 Word |
| 数据层 | `raw/`、`wiki/`、`data/`、`outputs/` | 原件、知识页、内部状态、产出 |

依赖方向是单向的：入口调用业务，业务调用基础，基础读写数据。`ingest` 会调用 `filing` 和 `fin_calc`，`filing` 又会调用 `ingest` 的合并函数；这是业务层内部的小循环，不涉及入口层。

网页和命令行不是两套实现。`manage.py ask` 调用 `ask.ask()`，网页 `/api/ask` 也调用它；`manage.py ingest` 调用 `ingest.run_all()`，网页上传则用 `_pipeline` 把 `classify_one` 和 `ingest_one` 串成两条线程。区别只在进度展示、会话存储和任务卡片。

## 4. 目录与模块地图

### 4.1 目录

| 路径 | 维护者 | 内容 | 说明 |
|---|---|---|---|

| `wiki/sources/` | 程序 | 来源摘要页 | 每份材料一页，`type: source` |
| `data/manifest.json` | 程序 | 已摄入清单 | 锚点合法性的第一依据，也是原文件页的清单来源 |
| `data/extracts/*.units.json` | 程序 | 逐页/逐块文本缓存 | 文件名去扩展名；提取一次复用 |

| `data/llm_log.jsonl` | 程序 | LLM 调用日志 | 一行一次调用，含任务、模型、字符数、token、成败 |
| `data/audit-<时间戳>.json` | 程序 | 审校结构化结果 | 修复向导的数据源 |
| `data/report_jobs/<id>.json` | 程序 | 行业研报任务 | 状态机真源，服务重启后按 `/continue` 续跑 |
| `data/report_jobs/<id>.candidates.json` | 程序 | 沉淀候选 | A/D/E 三类，勾选后写入 wiki |
| `outputs/audit-<时间戳>.md` | 程序 | 审校报告 | 只在审校页展示 |
| `outputs/report-*.md` | 程序 | 用户要求的报告 | 正文经 `/outputs/<name>` 查看；行业研报另有同名 `.docx` 与 `大纲-*.md`，入口在报告页 |
| `outputs/charts/` | 程序 | 研报图表 | 行业研报管线生成的 PNG |
| `.claude/` | 人 | 会话配置层 | 根 `CLAUDE.md`、十个技能、按公司/行业分流的六个研报子代理（另留三个通用）、写页校验钩子 |
| `schema/` | 人 | 规范与字典 | 规则文件，不参与运行时代码导入，`filing_items.json` 例外 |
| `src/` | 人 | 业务代码 | 见下表 |
| `src/web/` | 人 | Flask 应用 | 页面、API、模板、静态资源 |
| `tests/` | 人 | 测试脚本 | 独立运行，不是 pytest 用例 |
| `app/`、`scripts/` | 无 | 早期目录残留 | 只剩 `__pycache__`，没有源码，也不被任何模块导入 |

`.env` 存 API Key，已被 `.gitignore` 排除；`raw/` 与 `data/extracts/` 同样被排除。`config.json` 入库，里面只有端点和模型名，没有密钥。

## 6. 数据契约

### 6.1 raw：原始材料层

支持 `.pdf` 与 `.docx`。旧版 `.doc` 在网页上传时被拒，提示另存为 `.docx`；`pdf_extract` 也没有 `.doc` 分支。

取名线的输入是 `raw/inbox/`，只处理该目录第一层的 PDF/DOCX。`classify_one` 读取开头约 2600 字符，让模型返回：

```json
{
  "kind": "report | filing | policy",
  "broker": "出具方",
  "topic": "主题或公司",
  "industry": "行业",
  "date": "YYYYMMDD",
  "reason": "判断理由"
}
```

程序拼名的规则是 `出具方_主题+类型词_日期.扩展名`。类型词固定为研报、财报、政策文件。只有日期严格匹配 8 位数字才拼进文件名。拼完用 `sanitize` 去掉 `[ ] # |` 与空格等不安全字符，再用 `unique_target` 处理重名。实际例子：

```
东吴证券_智能汽车研报_20260921.pdf
中国汽车流通协会乘用车市场信息联席分会_乘用车市场研报_20260717.pdf
比亚迪财报_20260300.pdf
东吴证券_整车研报_20260921.pdf
```

目标目录由类型决定。研报进 `raw/reports/<industry 或 topic 或 未分类行业>/`，财报进 `raw/filings/<topic 或 未分类公司>/`，政策直接进 `raw/policies/`。

整个 `raw/` 在设计上是人工管理层。程序只在两个时刻动它：取名线把文件从 `inbox` 移到正式目录；原文件页删除时移除原件。其余读取都是只读。`raw_file_index()` 会同时索引 `reports`、`filings`、`policies`、`inbox` 四个目录，所以还在收件台的文件也能在原文查看器里打开，但原文件页会排除 `inbox`，因为它还不算入库材料。

### 6.2 manifest：已摄入清单

`data/manifest.json` 是一个对象，唯一键是 `files` 数组。每个条目字段如下。

| 字段 | 类型 | 含义 |
|---|---|---|
| `file` | string | 文件名，锚点里使用的名字 |
| `path` | string | 相对项目根目录的路径 |
| `sha256` | string | 文件内容哈希，幂等依据 |
| `unit` | `page` / `para` | PDF 按页，DOCX 按文档块 |
| `count` | int | 单元总数 |
| `report_date` | string / null | 研报日期或财报报告期截止日 |
| `source_type` | `report` / `filing` / `policy` | 来源类型 |
| `ingested_at` | ISO 时间 | 摄入完成时间 |
| `topics_touched` | string[] | 触及的 wiki 页面标题 |
| `entries_count` | int | 写入的知识行数 |
| `focus` | string[]，可选 | 本次导入的关注点 |
| `focus_hits` | string[]，可选 | 命中关注点的条目片段 |

清单的并发规则写在 `src/ingest.py` 顶部：`MANIFEST_LOCK` 是一把 `threading.RLock`。`save_manifest()` 整份写盘，`append_manifest()` 只追加本轮新增条目，并按 `(file, sha256)` 去重。摄入线每处理完一份就调用 `append_manifest`，而不是整份覆盖，这样并发的删除操作不会被一份旧清单冲回来。删除线则在 `MANIFEST_LOCK` 内读取、修改、写回完整清单。

### 6.3 wiki：知识页面

每个页面由 YAML frontmatter 与 Markdown 正文组成。必填字段是 `title`、`type`、`sources`、`updated`。可选字段是 `aliases`、`summary`、`history`、`focus`、`focus_hits`。实际例子，比亚迪页：

```yaml
---
title: 比亚迪
type: company
sources:
- raw/filings/比亚迪/比亚迪财报_20260300.pdf
updated: 2026-10-13
history:
- 2026-10-13 财报摄入 比亚迪财报_20260300.pdf（175 条）
- 2026-10-13 会话中提取（+4 条）
aliases:
- '002594'
summary: 比亚迪财报结构化数据（2025FY）
---
```

`type` 决定目录：company → `wiki/companies/`，industry → `wiki/industries/`，concept → `wiki/concepts/`，source → `wiki/sources/`。页面文件名是 slug；新建页面时标题先经 `classify.sanitize` 去掉路径分隔符等字符，`wiki.slug_to_path` 只负责把类型映射到目录并拼 `.md`。

正文按固定章节组织。`src/config.py` 的当前枚举是：

```
company  : 公司概况 / 行业格局 / 经营与财务 / 盈利预测 / 估值 / 分析观点 / 风险提示 / 其他
industry : 行业概况 / 行业格局 / 经营与财务 / 盈利预测 / 估值 / 风险提示 / 其他
concept  : 定义与口径 / 方法要点 / 政策背景 / 应用示例 / 其他
```

`source` 不在枚举里，来源页不强制分节，材料信息与贡献两节按出现顺序渲染。`wiki.render_page` 先按枚举顺序输出已有章节，枚举外的章节按出现顺序追加在后面。所以旧页面里多出来的章节不会丢，但也不会被枚举排序。

正文一行一条知识，行首 `- `，句尾锚点。四类结构化行的实际样式：

```
【数据】2025FY 合并 货币资金 = 75,424,747,000 元 [[比亚迪财报_20260300.pdf#p123]]
【数据】2025FY 合并 营业收入 = 803,964,958,000 元 [[比亚迪财报_20260300.pdf#p11]]
【指标】2025FY 毛利率(累计) = 0.1774 [[比亚迪财报_20260300.pdf#p11]][[比亚迪财报_20260300.pdf#p126]]
【指标】2025FY CCC(期末) = -9.8706
【管理层】「本集团主要从事新能源汽车业务……」——经营说明 [[比亚迪财报_20260300.pdf#p13]]
【观点】2025FY 比亚迪呈现「规模仍在扩张、利润与自由现金流承压」的格局…… [[比亚迪财报_20260300.pdf#p16]]
```

锚点语法只有两种：`[[文件名.pdf#pN]]` 与 `[[文件名.docx#paraN]]`。文件名不带路径，必须全库唯一。DOCX 的 `paraN` 是文档顺序的块号，段落和表格都算块，与网页对照视图显示的块号一致。文件名不得含 `[ ] # |` 与空格，取名线会清理。

页面之间用 `[[页面标题]]` 互链。`wikilinks_of` 只认这种双链；`/find/<target>` 按标题或 slug 找到页面并跳转。双链指向不存在的页面会被 `validate` 报错。

`wiki/index.md` 是给人看的索引文件，按公司、行业、概念、来源分节，每节一张表，列是页面、别名、摘要、来源数、条目数、更新。问答选页并不直接读这个文件；`ask._index_pages` 从页面对象生成条目，`wiki.compact_index_text` 再把非来源页拼成 `slug | 类型 | 别名 | 摘要` 的紧凑文本给模型。两者内容同源，但实现上 `index.md` 不参与检索。`wiki/log.md` 是 Markdown 表格，每次摄入、提取、审校、修复、报告、删除都追加一行。

当前 96 个页面：公司 70、行业 6、概念 14、来源 6。非来源页 594 行，来源页 34 行，全库 628 行。来源页的“知识行数”是材料信息与贡献说明，不是知识条目。

条目最多的是比亚迪（186 行）、汽车行业（148 行）、中国乘用车市场（36 行）、智能汽车（33 行），其余多为国信证券研报拆出的单条公司页。公司页数量多不等于覆盖深，单条页只够回答“这家公司在这份研报里被提到什么”。

### 6.4 data/fin：财报结构化数据

一份公司一个 JSON，例如 `data/fin/比亚迪.json`。顶层结构：

```json
{
  "slug": "比亚迪",
  "company": "比亚迪",
  "aliases": ["002594"],
  "periods": {
    "2025FY": {
      "period_end": "2025-12-31",
      "audit_opinion": "标准无保留意见",
      "source": "raw/filings/比亚迪/比亚迪财报_20260300.pdf",
      "items": {},
      "items_parent": {},
      "quotes": [],
      "indicators": {}
    }
  }
}
```

`items` 是合并口径科目，`items_parent` 是母公司口径。每个科目条目的结构：

```json
{
  "v": 803964958000.0,
  "a": "[[比亚迪财报_20260300.pdf#p11]]",
  "statement": "主要会计数据",
  "listed": true
}
```

`v` 是换算成元的数值；`a` 是锚点字符串，可能包含多个锚点；`statement` 是来源报表或“主要会计数据”；`listed` 表示该科目是否在 `filing_items.json` 字典内。

`quotes` 每条是 `{text, context, page}`，`context` 取“经营说明 / 指引 / 政策变更 / 风险提示”等。`indicators` 每条是 `{v, a}`，`v` 是数值，百分比与倍数以小数存，`a` 是取数科目的锚点列表。

当前比亚迪只有 `2025FY` 一期，145 个合并科目、116 个母公司科目、22 个指标、8 条管理层引述，审计意见是标准无保留意见。因为缺少上年同期与季度数据，单季、平均余额、同比、部分 TTM 指标没有算出来。22 个指标是：


## 7. 流程 A：上传、取名、摄入

### 7.1 入口分流

网页上传走 `POST /api/upload`。前端只接受 `.pdf` 与 `.docx`，后端再校验一次后缀。每个文件以原名（清理危险字符后）存进 `raw/inbox/`，重名自动加 `-2`。如果首页“关注点”填了内容且勾了开关，前端把数组 JSON 放进 `focus` 字段，后端解析后传给两条线。

命令行 `python manage.py sort` 只做取名，不摄入；`python manage.py ingest --all` 直接扫描 `raw/reports|filings|policies`，不经过收件台。

网页上传会启动两个后台任务：

- `classify` 任务：取名线，总步数是文件数。
- `ingest` 任务：摄入线，总步数也是文件数。

两条线通过 `queue.Queue` 连接。取名线每成功归类一份，就把目标路径放进队列；摄入线阻塞在 `queue.get()`，取到一份就摄入一份。取名线不等待摄入完成，继续处理下一份。取名线结束后放一个 `None` 作为收工信号，摄入线把队列里剩余的做完再退出。

### 7.2 取名线

`classify.classify_one(path)` 的步骤：

1. `pdf_extract.first_text(path)` 读取开头约 2600 字符。PDF 逐页取，DOCX 逐块取，累计到 2600 字符为止。
2. 如果开头没有任何文字，判定为扫描版或空文档，文件留在收件台，任务结果记 `ok=false`。
3. 调 `llm.chat(task="classify", response_json=True)`，prompt 要求返回 `kind`、`broker`、`topic`、`industry`、`date`、`reason`。
4. 如果 `kind` 不在 `report/filing/policy` 里，拒绝，文件留在收件台。
5. `build_filename` 拼名，`target_directory` 选目录，`unique_target` 处理重名，`shutil.move` 移动。
6. 返回 `{ok, file, renamed, target, kind, reason}`。失败时返回 `{ok:false, error}`，文件不动。

这一步只调用一次 LLM，温度 0.0。它不做内容理解，只做“这是什么、该叫什么、放哪里”。

### 7.3 摄入线

`ingest.ingest_one(path, manifest, focus)` 是通用入口。顺序如下。

1. 计算 SHA256。如果 manifest 里已有相同哈希，打印“已摄入过”，返回 `None`。
2. 如果文件名与已摄入条目相同但哈希不同，打印警告：旧锚点会指向新文件内容。这是唯一没有自动避免的锚点风险，靠文件名带日期规避。
3. `pdf_extract.extract_to_store(path)` 提取全部单元，写 `.units.json`，返回 `units`、`count`、`scanned`、`unit_kind`。
4. 如果 `scanned` 为真，拒绝编译。扫描版检测只对 PDF 生效：有效页（字符数不少于 20）的平均字符数少于 `min_chars_per_page` 50 就判扫描版。DOCX 不判。
5. 如果所有单元都没有文字，拒绝。
6. 如果 `source_kind(path)` 是 `filing`，转入 `filing.ingest_filing`，不走通用编译。
7. 否则调用 `compile_file`，把单元文本按页/段标记拼给模型，要求返回若干主题，每个主题带类型、别名、摘要、分节、知识行。超过 40 个单元才分段，每段 20 页；每段独立调用，结果按主题合并。
8. `_valid_lines` 逐行检查锚点。每条必须有锚点，所有锚点必须指向本文件、单元类型一致、序号在 1 到 `count` 之间。不合格的行丢弃并计数。重复行去重。
9. `plan_merge` 决定每个主题是并入已有页还是新建。先用标题与别名做规范化匹配（去空白与间隔号、casefold），命中且类型相同就并入；剩下的交给 LLM，给出现有索引与待定主题，让模型返回 merge/create 决策；模型没覆盖到的主题默认新建。
10. `_apply_merge` 把新行追加到对应节末尾，已存在的完全相同的行不重复加。渲染新正文后，断言旧锚点集合是新锚点集合的子集；不满足就抛异常，不写盘。然后更新 `sources`、`updated`、`aliases`、`history`。
11. `_apply_create` 新建页面。slug 用标题清理后的结果，重名加 `-2`。frontmatter 写 `title/type/sources/updated/history`，有别名和摘要再加。
12. `_write_source_page` 在 `wiki/sources/` 生成来源摘要页，页名是文件名去扩展名，正文写材料信息与贡献主题页。
13. 如果本次有关注点且模型返回了 `focus_hits`，`_tag_focus_pages` 把关注点与命中片段写进主题页 frontmatter，最多保留 50 条命中。
14. 把条目追加进内存里的 manifest，返回 `{file, entries_count, log}`。

`entries_count` 是该文件编译出的所有主题的所有行数，不是新增到页面的行数；如果某些行因为页面里已存在而被跳过，这个数仍按编译结果算。

### 7.4 收尾

网页两条线的摄入任务在队列结束后调用 `ingest.finish(load_manifest(), results)`。命令行 `run_all` 在循环结束后调用同一个函数。`finish` 做四件事：

1. `save_manifest` 整份落盘。
2. `wiki.rebuild_index_md(load_pages())` 重建总索引。
3. `wiki.append_log("ingest", summary)` 追加日志。
4. `validate.validate_all()` 全库校验，打印问题清单。

网页摄入线在每份材料后调用 `append_manifest`，只追加本轮新增的 `(file, sha256)`；收尾时再整份落盘。这样即使删除任务同时在跑，也不会把已删除的条目写回来。

### 7.5 关注点

关注点是可选的导入提示。前端把每行一个关注点组成数组，随上传发给后端。编译 prompt 里会多一段“本次重点关注”，要求模型优先保留命中条目，并把命中片段放进 `focus_hits`。它不影响锚点校验，也不改变合并规则；只是让模型在提炼时有所侧重，并把命中标记写进页面 frontmatter。

## 8. 流程 B：财报四段式

财报不走通用编译。`ingest_one` 发现 `source_kind == "filing"` 就调用 `filing.ingest_filing`。这条链路对应 `schema/财报摄取-skill.md` 的七步，代码里压缩成四段：定位、抄录、勾稽与计算、落库。

### 8.1 定位

`_locate(path, units, targets)` 把每页开头一段文字拼成页首映射，让模型返回：

```json
{
  "company": "公司规范名",
  "code": "股票代码",
  "period_type": "Q1 | H1 | Q3 | FY",
  "period_end": "YYYY-MM-DD",
  "audit_opinion": "标准无保留意见",
  "sections": {
    "合并资产负债表": [页码],
    "合并利润表": [页码],
    "合并现金流量表": [页码],
    "合并所有者权益变动表": [页码],
    "母公司资产负债表": [页码],
    "母公司利润表": [页码],
    "母公司现金流量表": [页码],
    "母公司所有者权益变动表": [页码]
  }
}
```

代码会校验页码是否在 1 到总页数之间；根据 `period_end` 的月份推断报告期类型，模型给的类型会被覆盖；要求 `period_type` 与 `year` 都存在，否则抛错。这里有一个潜在缺陷：`year` 只在 `period_end[:4].isdigit()` 为真时赋值，如果模型给了合法 `period_type` 但 `period_end` 为空，后面的 `if not ptype or not year` 会触发 `UnboundLocalError`。当前数据没有触发，因为财报的 `period_end` 都有值。

带目标数据摄入时（研报管线补年报、首页关注点），提示词追加一段目标清单，要求另返回 `targets: [{item, pages}]`，给出每个目标数据实际出现的页。这些页与主要会计数据页、MD&A 页一起进入目标数据补抄，最多 12 页。

### 8.2 抄录

`_transcribe(path, units, meta)` 按报表分批取页，每批最多 6 页（`BATCH_PAGES=6`），把页面文本和表格文本一起给模型，要求返回结构化行：

```json
{"statement": "资产负债表", "scope": "合并", "item": "货币资金", "value": "75,424,747", "unit": "千元", "page": 123}
```

模型返回的 `scope` 会被页面归属覆盖：如果该页属于合并报表区间，就按合并算；属于母公司区间，就按母公司算。这样避免模型把两套表混在一起。

`_eq_fallback` 是所有者权益变动表的机械兜底。权益表行名歧义大，模型容易抄错列；代码会在检测到报表单位后，用固定规则从右往左取第 4 个 token 作为数值，覆盖模型抄列的权益表行。这个兜底只处理合并权益表。

`_detect_unit` 从资产负债表首页或上一页找“单位：元/千元/万元”的声明。`_normalize_rows` 做四件事：按全局单位覆盖行单位；用 `normalize_item` 归一科目名；用 `to_yuan` 换算成元；检查同一科目是否出现数量级重复（例如同一条目同时以元和千元出现），有则告警。归一化后得到 `cons`（合并）与 `parent`（母公司）两个字典，以及丢弃行数。

### 8.3 勾稽与计算

`fin_calc.check_reconciliations({科目: 数值}, tol, supp_net_profit=None)` 跑四条规则：

- R1：资产总计 = 负债合计 + 所有者权益合计。
- R2：现金流量表的净增加额 = 经营、投资、筹资三项净额之和加汇率影响；期末现金减期初现金 = 净增加额。代码里是两条子校验。
- R3：未分配利润期末 = 期初 + 归母净利润（缺则用净利润）+ 提取盈余公积 + 对所有者或股东的分配，按报表原符号代入代数和；容差放宽 5 倍。
- R4：净利润 = 现金流量表补充资料起点净利润。`src/filing.py::_supp_net_profit` 从 `cf_supp` 页机械解析「净利润」行的本期金额，季报未披露补充资料、报表单位识别不出或找不到该行时跳过。

容差来自 `config.ingest.filing_check_tol`，当前 0.005，即 5‰。任何一条失败，`ingest_filing` 打印失败项并返回 `None`。此时不写 `data/fin/`、不写 wiki、不写 manifest；只留下 `.units.json` 缓存。人工核对后重跑摄入即可。

勾稽通过后，`fin_calc.compute_indicators(periods, pk)` 计算派生指标。它先取当期科目，再按需要取上年同期、上一报告期、TTM、平均余额。通用企业的指标分八组：

| 组 | 指标 |
|---|---|
| 盈利能力 | 毛利率(累计/单季/TTM)、核心营业利润率(自定义)、营业利润率、净利率、归母净利率 |
| 股东回报 | ROE(加权披露/期末/平均/归母平均/TTM)、ROA(平均)、ROIC |
| 杠杆 | 资产负债率、长期负债率、权益乘数 |
| 流动性 | 流动比率、速动比率、保守速动比率 |
| 周转 | DSO(期末/平均/平均含票据)、DIO(期末/平均)、DPO(期末/平均/平均含票据)、CCC(期末/平均/平均含票据) |
| 现金 | 获现比(TTM)、资本支出(元)、FCF(标准)、FCF(严格)、股东盈余(元) |
| 成长 | 营收同比、营收单季同比、归母净利同比、归母净利单季同比 |
| 每股 | EPS-单季(近似) |

缺科目或缺上年数据的指标不报错，放进 `missing` 清单。允许近似的指标会带 `degraded` 标签，例如 ROIC 缺利息费用时用财务费用近似，指标名变成 `ROIC(degraded)`。百分比与倍数以小数存，例如 0.1774 表示 17.74%。

当前比亚迪只有一期数据，实际落 22 个指标；`毛利率(单季)`、`ROE(平均)`、`ROA(平均)`、`总资产周转率`、各类同比等因为缺上年/上季数据没有算出来。

### 8.4 落库

`ingest_filing` 在勾稽通过后：

1. 用公司名与代码找已有公司页；找不到就用清理后的公司名新建。
2. 读 `data/fin/<slug>.json`，没有就初始化。
3. 把当期数据写进 `periods[pk]`，包含 `period_end`、`audit_opinion`、`source`、`items`、`items_parent`、`quotes`、`indicators`、`targets`。
4. `_render_lines` 生成三类行：【数据】按合并科目逐条，【指标】按指标逐条，【管理层】按引述逐条；`_render_target_lines` 另生成目标数据行。合并科目进 wiki，母公司科目只进 JSON，不进页面。
5. 并入或新建公司页的“经营与财务”节。合并仍走 `_apply_merge`，受只增不减断言保护。
6. `_save_store` 原子写 `data/fin/<slug>.json`。
7. `_write_source_page` 写来源页，材料信息额外包含审计意见、报告期、目标数据条数、字典外科目、缺失指标。
8. 往 manifest 追加条目，`entries_count` 是四类行总数；带目标时条目额外记 `targets` 清单。
9. 写 `.filing.json` 调试转储（含补充资料起点净利润、目标清单与目标行）。

当前比亚迪的结果：268 页，145 个合并科目，116 个母公司科目，22 个指标，8 条管理层引述，175 行进页面，审计意见标准无保留意见。145 + 22 + 8 = 175，与 manifest 的 `entries_count` 一致。

### 8.5 研报目标数据补抄

三条摄入路径（首页上传、取数页、研报管线补缺口）最终都走 `ingest.ingest_one`，财报类文件由它分流到 `filing.ingest_filing`。年报取数在取名时强制 `force_kind="filing"`（`classify_one`），不依赖模型把年报判成财报；其余文件按取名结果进 `raw/reports/` 或 `raw/filings/`，只有后者走财报流程。研报管线在缺口勾选后，把本次勾选的数据缺口整理成目标清单（`industry_report._gap_targets`，文档类缺口如年报、公告、研报本身不进清单），随 `fetcher.run_fetch(..., targets=...)` 一路传到 `ingest_inbox`／`ingest_snapshot`／`pipeline.build_lines`／`ingest_one`。首页关注点也并入目标清单。

`filing._target_rows` 在四表抄录之外，用目标清单再跑一轮取数：扫描目标是定位页、主要会计数据页与 MD&A 页，结果为 `item`、`scope`（年度、口径）、`value`、`unit`、`page`、`quote`。逐条规则：原文没有就不输出，不用相近指标顶替，不估算；与四表已抄科目同口径同数值的行由 `_drop_target_dupes` 略过。目标行以 `【数据】{报告期} 目标 {数据名}（{口径}） = {数值} {单位} [[锚点]]` 写入公司页“经营与财务”节，同时进 `data/fin/<公司>.json` 的 `periods[pk].targets`。

这条支路只受目标清单触发，不改变固定科目字典，也不参与勾稽；勾稽仍只看四表科目。港股以港元列示的财报仍抛 `UnsupportedFiling` 改走文本编译，目标数据此时只能按关注点提炼，拿不到 `【数据】目标` 行。

### 8.6 财报链路的边界

LLM 只做定位与抄录，不做勾稽、不做指标计算、不做判断。勾稽与指标全部是 `fin_calc` 的确定性代码。摄取层不产出趋势评论、好坏判断、阈值评价、预测；这些只能出现在问答层，并以【观点】经用户确认后沉淀。

银行、保险、证券专用指标尚未实现。`filing_items.json` 里有对应的科目标签，但 `compute_indicators` 目前只算通用企业指标。金融企业的财报可以摄入科目，但 NIM、不良率、拨备覆盖率、已赚保费等专用指标不会自动生成。

## 9. 流程 C：问答与三级回退

### 9.1 意图判别

`ask._detect_intent(question)` 先调一次模型，返回：

```json
{"intent": "chat | report", "title": "报告标题", "domain": "general | finstmt", "report_type": "industry | company | builtin"}
```

`intent=report` 时，`ask.ask()` 直接返回 `{kind:"report", title, domain, report_type}`，不选页、不作答。网页收到后按 `report_type` 分流：`industry` 与 `company` 起 `industry_report.start_job`（job 存 kind 区分两类），`builtin` 起原有 `report.generate` 任务；管线启动异常时自动回落到内置底稿。命令行 `manage.py ask` 没有网页确认关卡，行业研报与公司研报也走内置四段式，并打印提示。

`domain=finstmt` 表示问题涉及报表数据、比率、盈利、现金流、偿债、周转、地雷、审计意见等。这个标记会决定是否在问答、深查、报告三处提示词里注入 `FIN_ANALYSIS_BLOCK`。注入内容是财报分析纪律：先盘数据再判断、指标必带口径与报告期、阈值注明出处并提示 A 股适用限度、地雷六特征逐项过数、缺数明说、结论分层。

### 9.2 选页

`_select_pages` 取所有非来源页的索引条目，拼成紧凑文本：

```
slug | 类型 | 别名/别名 | 摘要
```

连同最近 4 轮问答摘要和问题一起给模型，要求返回：

```json
{"selected": ["slug1", "slug2"], "reason": "选择理由", "use_index": false}
```

程序只保留存在于索引里的 slug。`use_index=true` 表示这个问题问的是知识库整体（例如“库里有哪些行业”），不需要读页面全文，直接用索引作答。

提示词要求最多选 `ask.max_pages` 页，当前 8；程序只过滤不在索引里的 slug，不按数量截断，模型多选会全部采用。选页只看索引摘要，不看全文；这是刻意取舍，也是深埋细节可能漏选的根因。

### 9.3 作答

如果没有触发 `use_index` 且选到了页面，进入第二步：

1. 取选中页面中非来源页的正文，拼成 `### 标题（slug: ...）\n正文`。
2. 把 `ANSWER_PROMPT`、财报分析块（如果是 finstmt）、历史、页面文本、问题拼成一条用户消息。
3. 调 `llm.chat(task="answer")`，温度 0.2。
4. `strip_glitch` 清理模型偶发输出的 ASCII 乱码段。
5. `_allowed_from_pages` 构造允许的锚点集合：只取选中页面 frontmatter `sources` 里的文件，并且这些文件必须在 manifest 里，带单元类型与总数。
6. `_violations` 逐锚点检查：文件必须在允许集合里，单元类型一致，序号不越界。另外，如果答案里一个锚点都没有，但数字不少于 3 个，也判违规。这是为了拦住长提示词下模型整篇漏挂锚点的情况。
7. 有违规就追加一轮“请修正锚点后重新输出完整答案”，再校验一次。
8. 仍违规则在结果里记 `validation.ok=false`，网页在答案上方显示警告，命令行打印警告。

答案只能引用选中页面里出现过的来源文件。这条限制保证锚点不会指向模型临时想到的别的文件。

### 9.4 索引直答

`use_index=true` 或选页为空时，先尝试 `_answer_from_index`：

1. 取非来源页索引，机械统计各类型页数，放在索引文本头部，避免模型自己数长列表。
2. 用 `INDEX_ANSWER_PROMPT` 作答。
3. 如果答案包含 `UNANSWERABLE`，返回 `None`，表示索引答不了。
4. 索引回答不允许出现任何锚点；出现就重试一次。
5. 成功则返回答案，`step1.reason` 记为“选页为空，改用知识库总索引直答”。

索引直答适合“库里有哪些公司”“一共有多少页”这类元问题，不适合需要读正文的数据问题。

### 9.5 raw 文件名回退

索引也答不了时，进入回退第一级 `_suggest_raw_files`：

1. `raw_file_index()` 列出 `reports`、`filings`、`policies`、`inbox` 下所有 PDF/DOCX。
2. 对每个文件，从来源摘要页取摘要；没有来源页的标“未摄入”，有来源页但没有摘要的标“已摄入”。
3. 把文件名、相对路径、备注拼成最多 80 行，连同问题给模型，要求挑最多 5 个候选，返回文件名与理由。
4. 程序只保留确实存在于 raw 索引里的文件名。

有候选时，答案是一段固定话术，列出候选文件，请用户确认是否进一步查询；没有候选时，返回另一段固定话术，说明知识库中没有相关信息。两种都返回 `kind="referral"`，网页显示“进一步查询”按钮。

### 9.6 深查

用户确认后，网页 `POST /api/deep` 起后台任务，调用 `ask.deep_ask`。它有两种模式：

- 指定文件：用户点了某个候选文件，`files=[文件名]`。程序取该文件的全部单元文本，按 20,000 字符预算截断。
- 全库模式：用户没有指定文件，程序对全库 raw 文件做关键词粗筛。关键词取问题里长度不少于 2 的连续片段，长词再补二元切分；每个单元按命中关键词数打分，取分数最高的前 60 个单元，再按 20,000 字符预算装入。

拼好的片段带 `[文件名 | 第N页]` 或 `[文件名 | 第N段]` 标记，交给 `DEEP_ANSWER_PROMPT`。锚点校验放宽为“文件存在于 raw 且序号不超过提取单元数”，允许集合来自本次实际装入的单元。深查答案不自动写 wiki；如果答案合格，仍会生成沉淀提案，由用户决定。

### 9.7 会话提取

`ask._propose_distill(question, answer)` 只在答案锚点校验通过时调用。它让模型判断答案里是否包含跨页面综合出的新知识，返回：

```json
{
  "new_knowledge": true,
  "topic": "主题",
  "type": "company | industry | concept",
  "summary": "一句话摘要",
  "lines": ["【观点】...", "【数据】..."]
}
```

程序只保留至少有一个锚点、且所有锚点都出现在答案里的行。如果模型给的行没有锚点，但答案里有可用锚点，会调 `ANCHOR_REPAIR_PROMPT` 补挂一轮，再过滤。补挂后仍不合格的提案丢弃。

提案命中已有页时改为 merge，否则 create。网页把提案存进当前助手消息，弹出提取窗口，用户勾选行子集后 `POST /api/distill/apply`。`apply_distill` 把【观点】行放进“分析观点”节，其余行放进“其他”节，然后走 `_apply_merge` 或 `_apply_create`。写入时 `history` 记“会话中提取”或“会话中提取新建”，操作日志记 `ask`。

这里有一个实际行为值得知道：非【观点】的沉淀行不会回到它原本对应的章节，而是统一进“其他”。如果希望一条新数据进“经营与财务”，当前只能手工移动或改代码。

### 9.8 多轮上下文

`history_for_ask(cid, 4)` 从会话里倒着找最近 4 条已完成、`kind=answer` 的助手消息，配上它前面最近的一条用户消息，问题截 200 字、答案截 400 字，按时间正序返回。选页、作答、索引直答、深查都使用这段上下文。它支持“那它的毛利率呢”这类追问，但上下文很短，跨很多轮的指代可能丢失。

## 10. 流程 D：审校与修复

### 10.1 审校做什么

`audit.run(task_id)` 对每个非来源页做两类 LLM 检查，再做四类程序检查。

LLM 检查：

- 矛盾：同一页内是否存在事实矛盾。模型返回 `{kind:"矛盾"|"时点差异", note, quote_a, anchor_a, quote_b, anchor_b}`。程序用 `_quote_in_page` 验证引文确实在页面里，避免模型编造原文。`kind=矛盾` 进矛盾清单，`kind=时点差异` 单独列出，不报警。
- 内容缺口：页面缺少哪些关键信息。模型返回 `{point, why}` 列表。

程序检查：

- 过期：`updated` 早于今天减 `stale_days`（90 天），或 `updated` 无法解析。另外做观点老化：如果页面里有【观点】行，其报告期早于页内最新【数据】行，就把这条观点列入过期待复核。
- 未摄入：`raw/reports|filings|policies` 里存在、但文件名不在 manifest 里的文件。
- 孤立：没有任何其他页面用 `[[标题]]` 指向它的非来源页。
- 合并建议：标题互为包含的同类型页面；条目数少于 `orphan_min_statements`（5）且来源数不超过 1 的碎片页。

### 10.2 报告与 JSON

审校报告写到 `outputs/audit-<YYYYMMDD-HHMMSS>.md`，结构是：

```
# 审校报告 ...
范围：wiki/ 共 N 页（含来源摘要页）

## 矛盾（N）
### [页面] 说明
- A：「引文」锚点
- B：「引文」锚点

### 时点差异（N，属正常更新，不报警）
...

## 过期（N）
...

## 未摄入（文件 N，内容缺口 M 页）
...

## 孤立（N）
...
```

同时写 `data/audit-<时间戳>.json`，字段见 6.8。最后 `wiki.append_log("audit", ...)`。

当前唯一一份审校报告是 2026-10-13 22:20:15 的，矛盾 5、时点差异 0、过期 0、未摄入文件 0、内容缺口 3 页、孤立 0，没有合并建议。这份报告早于国信证券研报与统计局快照的摄入，结论已过时；现在六份正式材料都在 manifest，重跑审校不会再列未摄入文件。

### 10.3 修复向导

审校页读取最新 JSON，按类别列出可执行动作：

- `ingest`：摄入未摄入文件。动作带 `path`，`fix._fix_ingest` 校验路径在 `raw/` 内且存在，然后调用 `ingest_one`，落盘清单，重建索引，写日志。
- `merge`：合并碎片页或标题包含页。动作带 `from` 与 `into` 两个 slug。`fix._fix_merge` 把源页正文按节取出，走 `_apply_merge` 并入目标页，然后删除源页文件，重建索引，写日志。
- `mark_reviewed`：人工复核标记。动作带 `page`，在页面 history 追加“已人工复核（审校）”，不改正文。
- `conflict`：矛盾处理。动作带 `page`、`keep`（`a`/`b`/空）、`quote_a`、`quote_b`。选 A 或 B 时，删掉另一方的行；选空时双方都保留。删行是人工决策，`_fix_conflict` 直接改正文，绕过只增不减断言，并在 history 与日志留痕。

`fix.apply_fixes` 逐个执行，单个动作失败只记入 notes，不中断其他动作。最后追加一条 `fix` 日志。

## 11. 流程 E：报告、导出、删除

### 11.1 报告

报告入口有两个：问答里识别出 `intent=report`，或用户直接调用 `report.generate`。意图判别同时给出 `report_type`：行业研报、行业深度、行业月报、行业专题类与单一公司的研究报告（公司深度、公司研究、个股研报）走 `industry_report`（kind 分别为 industry 与 company），多公司对比、财务分析、快速底稿与其他报告走内置 `report.generate`；判别失败或拿不准一律落后者，保证总回退。

行业研报与公司研报共用 `src/industry_report.py` 状态机，每个阶段是一个独立后台任务，状态落 `data/report_jobs/<id>.json`（job 的 kind 区分两类；公司研报按 `.claude/skills/company-report/SKILL.md` 的八节权威框架定大纲，另取库内既有研报对该公司或其行业的覆盖章节，取料页强制含该公司页面且置顶；公司年报列为必选缺口，未补齐不能成文）：

1. `outlining`：样板先查库内新财富该行业组前 3 券商研报（`_library_top3_samples`，每家 1 份、至少 3 份）；不足时走慧博免登录榜单加东财下载链补齐（`sample_download_chain`：东财逐家下载综合最优 1 篇，排序为标题含深度/专题优先、其次页数、再次阅读量 count，某家在东财没有时按榜单名次顺延；库内已有的券商跳过不重复下载），仍取不满 3 份时按库内关键词研报补位并记降级日志（前 3 券商仍有缺时任务日志提醒用户可自行在慧博终端下载其研报 PDF，从网页上传或放 raw/inbox 摄入后重新发起），全空则由报告结构 skill 与行业概览 skill 双源合成大纲。机构研报逐页解剖框架解剖的就是这批已摄入的样板研报。行业研报的章节顺序固定为产业链 → 生产端 → 需求端 → 市场规模 → 竞争格局 → 增长驱动 → 盈利与估值 → 投资要点 → 风险提示，产业链放第一节，投资要点放在行业分析之后，不用卖方研报「投资要点开篇」的惯例；六节行业分析必须保留，缺料时合并相邻节。公司研报读 company-report 技能合成八节大纲，财务分析节以年报为锚。大纲写 `outputs/大纲-个人-<主题>-<日期>.md`，同时列数据缺口；公司研报自动加「公司年报」必选缺口（库内已有该公司的 FY 财报则不加）。
2. `outline_pending`：网页报告页展示大纲，可编辑后确认。确认时重列未摄入材料与数据缺口。
3. `gaps_pending`：缺口逐条勾选；带 `fetch` 的起取数任务，不勾的标 `skipped`，报告里保留「数据缺失」。公司年报缺口不可跳过，取数失败或未取到会停回本关卡。缺口补完或全部跳过后进入成文。
4. `writing`：按大纲分节成文，每节带取料页全文与版式纪律；节级锚点校验沿用 `ask._violations`，违规重试一轮；无锚点数据进缺口清单。
5. `charting`：按成文中的图表位出 PNG 到 `outputs/charts/`。
6. `reviewing`：程序抽验锚点位置文本是否含报告引用数字，模型审稿出问题清单，硬伤定向修复一轮。
7. `docxing`：pandoc 可用时转 Word，缺 pandoc 只交 md。
8. `candidates_pending`：把无锚点句按 A-F 分类，A/D/E 进候选；网页勾选后写 wiki，A/D 进「分析观点」的【个人观点】行，E 进「经营与财务」的带口径【指标】行，状态转 `done`。

服务重启后任务历史消失，但 job 文件还在；报告页点「继续」按当前状态续跑，停在 `outline_pending`、`gaps_pending`、`candidates_pending` 三个关卡时不动。异常落 `error` 并保留 `phase`，可修复后重试。

报告页每份任务带「删除这份研报」按钮（`industry_report.delete_job`），删任务记录、大纲、报告 md、Word、图表与沉淀候选；进行中的任务（`RUNNING_STATUSES`）拒绝删除，避免后台阶段把文件写回来。

内置 `report.generate` 做：

1. `_select_pages(question, history=None)` 选页。没有选中任何页面就抛 `ValueError`，报告任务失败。
2. 取非来源页正文，按 `REPORT_PROMPT` 要求生成固定结构：标题、核心结论 3 到 5 条、分节论述、数据表、风险与局限。每一句数据性陈述都要带锚点，只能引用给定页面出现过的来源文件。
3. 如果 `domain=finstmt`，注入财报分析块。
4. 锚点校验，违规重试一次；仍违规则在文末加“部分锚点未通过程序校验，请人工复核”。
5. 写 `outputs/report-YYYYMMDD-<标题>.md`，重名加序号。
6. 重建索引，写 `report` 日志。

进度通过 `tasks.update` 报 5、25、75、95。网页产出页轮询任务卡，完成后显示文件名；行业研报的阶段任务完成卡直接链到 `/report#job=<id>`。

### 11.2 Excel 导出

`/export` 页提供四张表与筛选条件：

| 表 | 内容 | 说明 |
|---|---|---|
| 科目数据表 | 合并口径科目，含公司、代码、报告期、报表、科目、亿元、元、锚点、来源、审计意见 | 只导出 `items`，不含母公司口径 |
| 派生指标表 | 指标名与数值 | 受下方缺陷影响，当前可能为空 |
| 条目溯源表 | 页面、类型、小节、正文、锚点、文件名、页码、纯文本、更新时间 | 默认不含来源摘要页 |
| 来源汇总 | manifest 里的文件、类型、日期、条目数、触及页面、路径、摄入时间 | 随清单实时变化 |

科目表只导出 `items`（合并口径），不导出 `items_parent`（母公司口径）。条目表默认只导出 company/industry/concept，不包含 source 页。筛选支持公司、报告期、页面类型、关键词、更新时间范围。

派生指标表当前有一个已确认的缺陷：`_iter_indicators` 遍历 `periods[pk]["indicators"]`，每个值是 `{"v": ..., "a": [...]}` 字典，但代码用 `isinstance(v, (int, float))` 判断，字典永远不满足，所以一条指标都导不出来。修正方向是取 `v["v"]`。另外，即使修好，当前代码把所有指标都乘 100 当作百分比，对 `资本支出(元)`、`FCF(标准)`、`FCF(严格)` 这类绝对额指标会放大 100 倍；指标表也没有单位列区分“百分比/倍/天/元”。这两个问题都需要在导出层一起处理。

### 11.3 删除原文件

原文件页 `GET /api/files` 调 `purge.file_entries()`。清单由两部分组成：

- `raw/reports|filings|policies` 里实际存在的文件（排除 inbox），每个带 manifest 条目、影响统计、缺失标记。
- manifest 里有、但 raw 里已经不在的文件（幽灵条目），供用户清掉。

`_impact` 预先扫描所有页面，统计每份文件被多少条知识行引用、涉及哪些页面、哪些页面会被清空。前端删除确认弹窗展示这些数字。

用户勾选后 `POST /api/files/delete` 起 `delete` 任务。删除不受摄入/审校互斥锁限制，因为它的清单写入与摄入共用 `MANIFEST_LOCK`，摄入只追加、删除只移除自己那份，两边不会互相覆盖；未摄入的 raw 文件也能从清单里单独清掉。`purge_files` 对每份文件在 `MANIFEST_LOCK` 内执行 `purge_one`：

1. 找到引用该文件的主题页行，逐行删除。删完如果页面一条不剩，整页删除。如果还剩行但 `sources` 被删空，按正文剩余锚点回填来源；如果剩余行一条锚点都没有，也整页删除。
2. 删除该材料的来源摘要页。
3. 删除 `data/fin/` 里 `source` 指向该文件的报告期；一份不剩就删掉整个公司 JSON。
4. 删除 `.units.json`、`.entries.json`、`.filing.json` 缓存。
5. 删除 raw 原件，并向上清理变空的子目录，停在 `reports`、`filings`、`policies`、`raw` 这几层。
6. 从 manifest 移除条目。
7. 全部删完后 `_drop_dangling_links` 扫描所有页面，把指向已删页面的 `[[双链]]` 降级成纯文字。
8. 重建索引，写 `delete` 日志。

当前原文件页会列出 6 份正式材料，全部在 manifest 里，其中统计局汽车产量快照引用 14 条、国信证券研报引用 304 条。

## 12. 后台任务与并发

`src/tasks.py` 是进程内任务注册表，不落盘。服务重启，任务历史消失，但业务数据已经落盘。

任务结构：

```json
{
  "id": "12位十六进制",
  "kind": "classify | ingest | audit | fix | report | fetch | delete | ask",
  "kind_label": "中文名",
  "status": "running | waiting | done | error",
  "total": 3,
  "current": 1,
  "percent": 33,
  "label": "任务卡标题",
  "detail": "当前步骤说明",
  "result": null,
  "error": null,
  "created_at": "ISO 时间",
  "acknowledged": false
}
```

`MUTEX_KINDS` 是 `{"classify", "ingest", "audit", "fix", "report", "fetch"}`。同类任务同一时间只允许一个在跑；后来的任务先把状态置 `waiting`，在前一个释放锁后自动接续。`delete` 与 `ask` 不在互斥集合里，问答不限并发，删除也不与摄入互斥。

`MAX_TASKS` 是 200。超过时从 `_ORDER` 头部淘汰，只淘汰已经 `acknowledged` 的任务；未确认的任务即使超过 200 也先保留。前端每 2 秒轮询 `/api/tasks`，拿未确认任务的快照；用户点掉完成卡片后 `/api/tasks/<id>/ack` 把任务从注册表移除。

并发安全靠三样东西：

- manifest 的 `RLock`。
- 摄入只追加、删除只移除的写策略。
- 每个页面写盘用临时文件替换（`write_page` 与 `_save_store` 都是 `tmp.replace`），避免读到半截文件。

仍然存在的竞态：两个摄入任务同时处理不同文件、又要并入同一页时，后写的一方可能覆盖先写的一方。`MUTEX_KINDS` 让 `ingest` 同类互斥，所以正常路径下不会有两个摄入同时改页面；但如果用户用两个进程各跑一个 `manage.py ingest`，互斥锁不跨进程，这个保护就失效。网页单进程运行是当前设计前提。

## 13. LLM 调用层

`src/llm.py` 统一两家 API 格式。

格式判断只看 URL 结尾：以 `/messages` 结尾按 Anthropic Messages 解析，否则按 OpenAI 兼容的 `choices` 解析。Anthropic 响应里只取 `type=="text"` 的块，跳过 thinking 块；OpenAI 响应取 `choices[0].message.content`。两家 usage 字段名不同，代码统一成 `prompt_tokens` 与 `completion_tokens`。

请求头统一带 `Authorization: Bearer <key>`；Anthropic 端点额外带 `anthropic-version: 2023-06-01`。超时是连接 10 秒、读 `read_timeout_s`、写 30 秒、池 10 秒。可重试状态码是 429、500、502、503、504，以及超时、传输错误、响应无正文、响应结构异常。重试次数 `max_retries=3`，退避是 2、4、8 秒，也就是最多 4 次请求。

模型选择用 `contextvars.ContextVar`。默认是 `config.json` 的 `llm.default`；`use_model(name)` 可以在当前线程/上下文里覆盖。后台任务各跑各的线程，两个请求用不同模型不会串。`active_model()` 返回当前实际模型名，网页答案头部标注它。

每次请求都会写 `data/llm_log.jsonl`：时间、任务、模型、输入字符数、输出字符数、token、成败、错误。失败的重试也各记一行。日志不含提示词与答案正文。

`chat(..., response_json=True)` 会从模型输出里找第一个 `{` 或 `[`，截到最后一个 `}` 或 `]`，尝试 `json.loads`。失败时追加一条“只输出合法 JSON”的修正消息，再请求一次；两次都失败抛 `LLMParseError`，错误信息带原文前 500 字。这是为了对付模型偶尔在 JSON 外裹 Markdown 围栏或解释文字。

相邻同角色消息会在请求前合并成一条。Anthropic 要求 role 交替，OpenAI 兼容格式也不受影响。

`extra_body` 从模型档案合并进请求体，当前配置是 `{"thinking": {"type": "disabled"}}`。智谱与火山都认这个字段；不关思考时，长输入可能因为深度思考顶爆 300 秒读超时，或者把输出额度耗在思考上。

### 14.3 原文对照

PDF 用打包的 PDF.js 渲染。`viewer.js` 读取 `file`、`loc`、`hl` 三个参数：`loc` 是 `pN`，定位到第 N 页；`hl` 是高亮词。渲染后取文本层，查找 `hl` 并加高亮。缩放按钮调整 `scale`。PDF 本身通过 `/file/<name>` 发送，`mimetype` 是 `application/pdf`。

DOCX 先由 `docx_html.docx_to_html` 转成 HTML。段落与表格按文档顺序编号，元素带 `data-n`，标题转成 `<h1>` 到 `<h6>`。查看器按 `loc=paraN` 找到对应块，滚动并高亮。Word 没有固定页码，所以锚点用块号；块号与查看器显示的一致。

锚点在页面正文里由 `render_md` 转成 `<sup class="cite">`，点击在新标签打开 `/viewer?file=...&loc=...&hl=...`。`hl` 取锚点附近的一段文字，用于文本层高亮。双链转成 `/find/<target>`。

### 15.1 全库校验

`validate.validate_all()` 检查：

- 必填 frontmatter：`title`、`type`、`sources`、`updated`。
- `type` 与所在目录一致。
- 【数据】【指标】【观点】行的格式：报告期前缀、` = `、数值可解析、口径括号闭合。

- `[[双链]]`：指向的页面标题存在。
- 索引：每个页面文件名出现在 `wiki/index.md` 里。

同样的规则收在 `src/wiki_check.py`。`validate.validate_all()` 调它做全库校验；会话写 `wiki/**.md` 时 `.claude/hooks/page_check.py` 调 `check_page()` 拦截坏页；网页的摄入合并、会话提取、报告沉淀在写盘前也调 `check_content()`，不通过抛 `RuntimeError`。三处共用一套规则，避免钩子与程序漂移。

它不检查知识内容的真假，不检查同一数据在不同页面是否一致，不检查锚点指向的页里是否真的有这句话。这些靠审校的 LLM 检查和人工复核。

5. 技能目录：`.claude/skills/` 下十个技能是否齐全。
6. 模型连通性：对 `config.json` 里每个模型发一句“请只回复两个字：正常”，记录耗时；默认模型不通则 selftest 失败。
7. 库外问答：问一个知识库外的问题，确认走 `referral` 回退；最后跑 `validate_all`。

selftest 会真实调用模型，产生 LLM 日志与费用。它也会启动一次完整的问答链路（意图、选页、索引直答/回退），不只是 ping。

## 17. 已知问题与风险

按影响从大到小排列。

### 17.1 Excel 派生指标表导不出数据

`src/excel_export.py` 的 `_iter_indicators` 把 `periods[pk]["indicators"]` 的每个值当成数字判断，实际值是 `{"v": 数值, "a": 锚点列表}` 字典。结果指标表只有表头，0 条数据。实测生成的工作簿：科目表 145 行、指标表 0 行、条目表 276 行、来源表 4 行。

修好类型判断后还有两个问题：所有指标统一乘 100 当百分比，绝对额指标（资本支出、FCF）会放大 100 倍；指标表没有单位列，无法区分百分比、倍、天、元。导出层的锚点列也硬编码为空字符串，没有取 `v["a"]`。这是当前最明确的功能缺陷。

### 17.2 test_purge 夹具过期（已修复）

`tests/test_purge.py` 已改为按当前清单动态计算预期，不再写死 3 份材料与 174 条引用。2026-10-28 全量测试通过。

### 17.3 财报定位的潜在 UnboundLocalError

`src/filing.py::_locate` 里 `year` 只在 `period_end[:4].isdigit()` 时赋值。如果模型返回合法 `ptype` 但空 `period_end`，`if not ptype or not year` 会先读 `year`，抛 `UnboundLocalError`。当前财报都有 `period_end`，没有触发。修法是初始化 `year = ""`，或在读 `year` 前先判断 `period_end`。

### 17.4 文档与实现漂移（已处理）

上一版第 5.3 节列出的七处在 2026-10-28 已全部处理：命名统一、章节枚举补齐、01/02/03 状态行更新、R4 实现、问答 skill 旧话删除、Query 规则对齐代码、【管理层】格式校验补上。当前没有已知的文档与实现漂移。后续改契约时同步改 5.1—5.3，避免再次积累。

### 17.5 校验覆盖不足

`validate_all` 不检查每条知识行是否真的有锚点（只检查已有锚点是否合法），不检查锚点指向的页里是否真有这句话，不检查内容真假。`CCC(期末)` 这类由多个指标算出的行没有锚点，是当前数据里真实存在的例外；`validate` 不会报。来源摘要页也没有锚点，这是设计允许的。

### 17.6 沉淀行的章节落点（已修复）

`apply_distill` 现按行首分流：【观点】【个人观点】进“分析观点”，【数据】【指标】进公司页或行业页的“经营与财务”，其余进“其他”。报告沉淀与会话提取共用这套分流。

### 17.7 selftest 依赖列表漏了 openpyxl

`manage.py` 的依赖检查列表是 `httpx/pdfplumber/flask/dotenv/yaml/markdown/docx`，没有 `openpyxl`。导出功能依赖 openpyxl；如果换环境时只跑 selftest，导出会直到点击才报 `ModuleNotFoundError`。当前环境已安装，不影响使用。

### 17.8 国信证券研报未摄入（已修复）

2026-10-28 首次尝试摄入时智谱返回 429「余额不足或无可用资源包」，重试三次失败。改用 DeepSeek-V4.1-Flash 重跑后已摄入，生成 304 条知识、85 个页面，manifest 与来源页齐全。

### 17.9 同名不同版本的锚点风险

摄入时如果发现文件名相同但 SHA256 不同，只打印警告，仍然继续。旧锚点会指向新文件内容。当前靠文件名带日期规避，但没有强制阻止。若用户手工替换同名文件，历史知识可能指向错误页面。

### 17.10 单机、无鉴权、无 OCR

Flask 只监听本地回环，没有登录。任何能访问本机 5000 端口的人都能读写知识库。扫描版 PDF 没有文本层会被拒绝，没有 OCR。旧版 `.doc` 不支持。双栏排版与复杂表格的文本流可能乱序，需要点角标对照原文人工抽查。PDF 文本层高亮对扫描件无效，但定位到页仍可用。

### 17.11 选页上限与索引依赖

问答提示词要求最多选 8 页，程序不硬截断，只看索引摘要。问题涉及很多页面或细节埋在正文深处时，可能漏选。深查回退能补一部分，但它依赖关键词粗筛与 20,000 字符预算，不是全库精确检索。知识库规模继续变大后，这个限制会更明显。

### 17.12 进程内任务与单进程假设

任务注册表在进程内存里，服务重启后任务历史消失。`MUTEX_KINDS` 是进程内锁，不跨进程。如果同时跑两个 `manage.py` 或两个 Flask 进程，互斥失效，可能出现页面覆盖。当前设计是单进程本地使用。

### 17.13 行业研报审校仍可能留软问题

审校阶段做了程序锚点抽验、模型审稿与一轮硬伤修复，但不保证清掉全部问题。2026-10-28 验证稿仍留下少量口径衔接说明过长、单月与累计降幅混用、部分句子缺具体数值等软问题；审校记录会原样展示，需人工复核后决定是否改稿。管线不会自动重写整篇。

### 17.14 默认模型余额耗尽会中断摄入与报告

默认模型 `glm-5.1` 的账户在 2026-10-28 验证时返回 429「余额不足或无可用资源包」。`llm.chat` 重试三次后抛错，摄入整份文件失败，研报任务也会停在 `error`。换用 `deepseek-v4.1-flash` 或充值后重跑即可；selftest 的模型连通性检查会先暴露这个问题。

### 17.15 pandoc 与 matplotlib 是可选依赖

转 Word 依赖 PATH 上的 pandoc，缺了只交 Markdown；出图依赖 matplotlib 与中文字体，缺了报告不含图表。selftest 会提示但不阻断。2026-10-28 验证环境两者可用，pandoc 在 `C:\Users\DELL\AppData\Local\Pandoc\pandoc.exe`，matplotlib 使用 Microsoft YaHei。

## 18. 操作手册

### 18.1 第一次运行

1. 确认 `.env` 存在。没有就从 `.env.example` 复制，填入 `ZHIPU_API_KEY` 与 `ARK_API_KEY`；只用一个模型时可以只填一个，另一个留空。
2. 跑 `python manage.py selftest`。它会检查依赖、配置、两个模型的连通性、库外回退、全库校验。默认模型不通会失败。
3. 跑 `python manage.py serve`，浏览器打开 `http://127.0.0.1:5000`。

### 18.2 日常摄入

网页：首页把 PDF/DOCX 拖进虚线框，或点击选择。上传后首页出现两张任务卡，一张“取名入库”，一张“摄入”。取名卡每完成一份，摄入卡就开始处理一份，不需要等全部改名完成。任务卡可以点掉，但点掉只是从界面移除，不影响后台。

命令行：`python manage.py sort` 只归类收件台；`python manage.py ingest --all` 摄入 `raw/` 正式目录全部材料；`python manage.py ingest --file raw/reports/...pdf` 只摄入一份；加 `--dry-run` 只提取预览，不调用 LLM 编译。

摄入失败先看任务卡的 `error` 与 `detail`，再看 `data/llm_log.jsonl` 最后几条，最后看 `data/extracts/*.units.json` 是否有文本。扫描版、空文档、锚点全不合格、勾稽失败是常见原因。

### 18.3 提问

首页或 `/ask` 输入问题。答案里的角标点开是新标签的原文查看器；PDF 定位到页并高亮，DOCX 定位到块。答案头部标注实际使用的模型。

如果答案是“知识库中没有该信息”并列出候选文件，点“进一步查询”会对候选原文深查。深查结果不自动进 wiki；如果模型认为有跨页面新知识，会弹提取窗口。

### 18.4 沉淀新知识

答案下方或任何页面弹出的提取窗口，列出模型认为值得沉淀的行。勾选认可的行，点“确认提取”。【观点】行进公司页“分析观点”节，其余行进“其他”节。已提取过的行不会再次出现。

命令行 `python manage.py ask "..."` 在检出提案时会打印行并问 `y/N`，输入 `y` 写入。

### 18.5 审校与修复

`/audit` 点“运行审校”，等任务完成。报告按矛盾、时点差异、过期、未摄入、孤立展示。修复向导按 JSON 列出动作，勾选后执行。摄入遗漏文件、合并碎片页、处理矛盾、标注复核四类动作可以分开选。

审校只给待人工复核的清单，不是自动结论。矛盾项附双方原文与锚点，需要点开原文判断。

### 18.6 生成报告

在问答里说“生成一份关于比亚迪和广汽的对比报告”之类，意图判别为 report 后起后台任务。产出页看进度，完成后点文件名查看。报告存 `outputs/report-*.md`，有锚点校验，违规会在文末标注。

### 18.7 导出

`/export` 勾选四张表、公司与报告期、页面类型、关键词、时间范围，点“导出 xlsx”。当前指标表有缺陷，导出前要知道它会是空的；科目表、条目表、来源表可用。

### 18.8 删除材料

`/files` 列出已入库材料与幽灵条目。勾选后点删除，弹窗显示这份材料牵连的知识条数、涉及页面、会被清空的页面。确认后起独立后台任务，页面有进度条。删除不可撤销；如果不确定，先在沙盒或备份里试。

### 18.9 出问题时看哪里

| 现象 | 先看 |
|---|---|
| 上传后没反应 | 首页任务卡、`/api/tasks`、浏览器控制台 |
| 取名失败 | 任务卡 error、文件是否在 inbox、开头是否有文字 |
| 摄入失败 | 任务卡 error、`data/llm_log.jsonl`、`data/extracts/*.units.json` |
| 财报挂起 | 控制台勾稽失败项、`data/extracts/*.filing.json` 的 `fails` |
| 问答答非所问 | `step1.selected` 与 `reason`、页面 frontmatter 的 `summary` 与正文是否准确 |
| 答案锚点警告 | 答案里引用的文件是否在选中页面的 sources 里 |
| 审校结果异常 | `data/audit-*.json`、`outputs/audit-*.md`、raw 与 manifest 差异 |
| 删除不干净 | `data/manifest.json`、`data/fin/`、`data/extracts/`、页面 `sources` |
| 导出报错 | openpyxl 是否安装、`data/fin/` 结构是否完整 |

这个项目的核心不是“让模型回答得更聪明”，而是“让每条知识都能回到原文、每次合并都不丢旧内容、每次写入都先过程序校验”。理解这一点，就能理解为什么目录这样分、任务这样排队、财报要单独走四段式、审校要人工确认后才能改页面。
