# 行业研报生成

## 前置条件

- wiki/ 已有该行业的行业页与公司页（`python manage.py audit` 无未摄入项）。库里没有的行业先走搜数据→摄入流程，再回来生成。网页研报管线在取料阶段自动检查未摄入材料并列入缺口清单，不硬挡
- 已摄入材料里必须有至少 3 份新财富该行业组前 3 券商的行业研报当样板（每家至少 1 份；某家券商在东财没有该行业研报时按榜单名次顺延补足 3 家）。不足时会话内先派资料员按样板链补（慧博免登录取榜单定前 3，东财免登录逐家下载综合最优的 1 篇），仍无则用 report-structure + sector-overview 双源合成大纲并在交付时说明降级

## 流水线分工（定稿，2026-10-24）

- 第 1、2 步（选样板、定大纲）归主线会话。编辑决策需用户确认。章节顺序按下文固定的行业分析逻辑，不由样板决定；样板研报只定叙事语感、行文密度与图表习惯，report-structure 与 sector-overview 框架负责查漏补缺（估值、格局）并给版式纪律。权衡结果固化进 outputs/ 大纲文件，每节写明论点、数据表、图表位、取料页面
- 第 3-6 步（取料、成文、自检、转 Word）派撰稿人代理执行。大纲是结构决策的唯一依据，撰稿人可翻样板研报找语感与行文密度，不重做结构权衡
- 第 5 步自检双保险：撰稿人自查后，审稿人代理独立复核（锚点抽验、数字核对、口径与排版）。审校发现的问题不留未处理：能修的修掉（残句删除、口径改写、锚点回挂报告里出现过的真实锚点，不编造数值），修后逐条复核；复核证伪的标误报并写明依据；实在修不掉的遗留条目必须附原因待人工定夺。交付时审校记录呈现处置结果（修复了什么、误报是什么、遗留什么与为什么），不是问题清单；硬伤全部处理完（修复或证伪）才交付
- 缺口数据由撰稿人列清单交回主线，主线派资料员补料，撰稿人不自己下载

### 网页端对照（2026-10-28 起）

网页问答识别为行业研报请求时，由 src/industry_report.py 状态机按本技能流程执行，三处网页确认关卡替代会话内的用户确认：大纲确认（outline_pending）、缺口勾选后派 src/fetcher.py 取数（gaps_pending）、成稿后 A-F 候选勾选沉淀（candidates_pending）。资料员、撰稿人、审稿人的活分别由取数任务、成文/图表/转 Word 阶段、review 阶段承担，规则与交付物同本技能。会话内仍可手工走 1-6 步，两边共用同一份 wiki、raw 与 outputs/。

## 流程

### 1. 选样板研报

样板只从新财富该行业组前 3 券商的研报里选，两步定位：先读慧博免登录榜单 `https://www.hibor.com.cn/author.html?year=<年>&bigtype=2`（bigtype=2 为新财富）匹配行业组、取前 3 券商；再逐家到东方财富研报中心挑综合最优的 1 篇，综合最优的排序是标题含深度/专题优先，其次页数多，再次阅读量高（东财列表接口的 count 字段）。每家 1 份、共至少 3 份；某家券商在东财没有该行业研报时按榜单名次顺延（第 4、第 5…）补足 3 家，并在大纲文件里注明顺延了谁、为什么。库内已摄入且出自这 3 家券商（含顺延后补上的）的行业研报直接复用，不重复下载。顺延也补不齐前 3 时不硬等：放宽为综合最优的库内或东财研报先成文，最后的审校记录写明前 3 占比（几份中几份出自前 3、缺谁）与补齐方法（慧博终端下载缺的券商研报 PDF 上传摄入，删除本报告重新发起后管线优先用库内研报），任务日志同步提醒；没有样板才退到双源合成大纲并注明降级。查看方式：读 `wiki/sources/` 来源摘要页，或 `python manage.py ask "库里有哪些该行业的研报"`。定下后读 raw/ 原件，摘出目录章节骨架和每节的功能。

### 2. 定大纲

三样东西合成大纲，存 `outputs/大纲-<主题>-<日期>.md`：

- `.claude/skills/earnings-analysis/references/report-structure.md` —— 机构研报逐页解剖框架（章节功能、图表位置、行文规范）
- `.claude/skills/sector-overview/SKILL.md` —— 行业全景报告的标准结构（市场格局、竞争定位、核心玩家、主题趋势）
- 样板研报的章节骨架 —— 中文卖方研报的本土写法（论点密度、图表习惯、风险提示写法）；章节顺序以下文固定规则为准，不照搬样板的「投资要点开篇」

机构研报逐页解剖框架解剖的对象是已摄入的样板研报，即第 1 步定下的至少 3 份新财富前 3 券商研报（含本轮资料员取回并已摄入的），不是库外或未摄入的研报。库里不足 3 份时先回第 1 步补样板，再定大纲；补不齐才走双源合成并注明降级。

大纲逐节写明：本节论点、需要的数据与数据表、图表位、对应的 wiki 页面。库里没有的数据当场列缺口清单。

行业研报的章节顺序固定按行业分析的展开逻辑，不套卖方研报「投资要点开篇」的惯例：产业链（上游、中游、下游与价值分布）→ 生产端（产能、产量、成本与供给格局）→ 需求端（需求结构、下游景气、渗透率）→ 市场规模（量价与规模测算）→ 竞争格局（份额、集中度、玩家分层）→ 增长驱动（政策、技术、渗透率、出口等）→ 盈利与估值 → 投资要点 → 风险提示。产业链放第一节，先交代行业怎么运转、钱在哪个环节；投资要点放行业分析之后，只做归纳，不重复前文论证。缺料时合并相邻章节，但产业链、生产端、需求端、市场规模、竞争格局、增长驱动六节必须保留。网页管线的大纲提示词与本条一致。

### 3. 取料

逐节从 wiki 取条目：按 kb-ask 技能直接读 `wiki/industries/`、`wiki/companies/` 页面，锚点原样复用；零散问题也可走 `python manage.py ask`（带程序校验，可顺手沉淀新知识）。缺口清单上的数据派资料员补，网页或 API 取数先按 data-sources 技能落快照（`<机构>_<主题>快照_<取数日期>.docx`，放 raw/reports/数据快照/），摄入后再写。

### 4. 成文

按大纲写 `outputs/report-<主题>-<日期>.md`。规则：

- 库内事实句句带锚点 `[[文件.pdf#p页码]]`，锚点只能指向已摄入文件
- 含数据的句子必须有锚点；无锚点的句子只能是判断、推断或行业常识，不得承载数据。外部来源也先落快照再挂锚点，不用（来源，日期）括号顶替；库里没有快照锚点的数据列缺口清单，不写进正文
- 派生值（ROE、毛利率、增速、占比、差额等）写成「数值（测算：公式）」，公式输入数字带锚点并挂在原始数字所在页；核对器只校验输入，不要求比值本身出现在原文
- 锚点挂在数字实际出现的页，跨页数字分别挂，禁止把整段数字统一挂到同一页码
- 模型补充、推断、行业常识不标【库外】，句尾无锚点即视为库外，与问答口径一致
- 估值对比表用 `.claude/skills/comps-analysis` 框架，竞争格局章节用 `.claude/skills/competitive-analysis`
- 行文遵守用户中文写作规范：少引号少冒号、删套话、拆长句、一句一事

### 5. 自检

- 对照大纲逐节查漏
- 抽查锚点，点开 raw 原文核对页码与内容
- 数字与 wiki 条目一致，句句可溯源
- 给正文无锚点句逐句分类：A 综合判断（跨材料、单页没明说）、B 复述漏锚（单份材料已有，补锚点）、C 口径方法、D 前瞻预测、E 推导计算、F 行文框架
- 把 A/D/E 三类列入候选清单，随稿交主线供用户勾选；A/D 类勾选后按【个人观点】写入，E 类勾选后按普通数据行写入并注明计算口径；B 类标明应补的锚点并在交稿前补上；C/F 留在报告，不进 wiki；D 类候选附预测条件与日期，E 类候选附复核过程与锚点

### 6. 输出

用 md-to-docx 技能把成稿转成排版规范的中文 Word，存 `outputs/`。成品报告一律走 `python outputs/convert_report.py <报告.md> <输出.docx>`：正文所有引用统一进尾注，[[锚点]] 转成上标编号加文末注释表，正文不留括号来源；同时去重封面标题、表格加表头底纹与边框与数值右对齐、图片居中、注释顶格、多编号升序（底层仍调 md-to-docx，pandoc 上标须转义方括号避免撞行内脚注语法）。（来源，日期）括号只作为旧稿兼容由脚本顺手收掉，新稿不许出现，SOURCE_RE 白名单也不再扩充

## 与内置报告的关系

报告请求分三条路。行业研报（行业研究/深度/月报类）走本技能，网页端由 src/industry_report.py 管线执行，成品带样板结构、图表与 Word。对比分析报告、财务分析报告、快速数据底稿等其余请求仍走内置 src/report.py（固定四段结构、纯库内、自动锚点校验），命令行 `manage.py ask` 的行业研报请求也落这条路（命令行无确认关卡）。第三条是会话内手工流程，即本技能原文 1-6 步。三者不冲突，内置底稿可以直接喂给本技能当素材。
