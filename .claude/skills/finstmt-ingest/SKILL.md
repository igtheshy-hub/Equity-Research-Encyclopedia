# 财报摄取（v1.4，已接入程序）

状态：已实现，2026-11-06 按 scripts/filing_pipeline.py 的实际行为校对。本文件自 schema/财报摄取-skill.md 迁入（2026-10-29，唯一副本），参考文档随迁（01、02、03 都在本目录 references/）。实现产物：scripts/filing_pipeline.py（四段式流程，`src/filing.py` 只是兼容入口，ingest_one 对 filing 类自动分流）、src/fin_calc.py（勾稽与指标计算器）、schema/filing_items.json（机器可读科目别名表）、data/fin/（结构化存储）。本文件是摄取 skill 的流程指令，引用三份参考文档：
- references/财报摄取-01-科目字典.md（科目清单、数据字段、勾稽校验）
- references/财报摄取-02-两岸术语映射.md（口径陷阱、阈值出处规则，旧格式科目归一规则引自它）
- references/财报摄取-03-多口径指标字典.md（派生指标公式与报告期处理）

## 口径定位（先读，防混淆）

本流程原生口径是 A 股（大陆企业会计准则，科目字典 version 2019b）。A 股财报（年报、季报）直接套用，不需要任何口径转化；坊间印象里「skill 是港股口径、A 股要靠三份文档转化」是反的。港股财报才是被兼容的特例：

- 以人民币列示的港股报表：科目名经 filing_items.json 别名表归一（如「權益總額」→「所有者权益合计」），费用与负债的括号减项由 `_fix_statement_signs` 翻正，权益变动表口径不同导致 R3 跳过
- 以港元列示的港股报表：整份拒收（UnsupportedFiling），改走文本编译，不产结构化行

三份参考文档的分工：01 是 A 股科目字典本体（含港股与旧格式别名，references/ 内）；02 是台湾 IFRS 术语到 A 股科目的映射，问答层的口径陷阱与摄取层的旧格式科目归一规则都引它；03 是派生指标公式字典（references/ 内）。

## 会话内何时用本技能

用：摄入出问题时排查（勾稽失败挂起、核心科目补录后仍缺挂起、港元拒收、重摄留重复行）；解释或核对【数据】【指标】【管理层】行格式与口径；把 data/fin 结构化数值与原文对照核数；理解科目归一行为（aliases 命中、字典外科目 listed=false）；目标数据补抄的取舍。

不用：日常摄入不需要会话参与，财报放 raw/filings 后 `python manage.py ingest --all` 自动分流，不要手动模拟流程；报表数字的分析判断、阈值评价归 finstmt-qa；选页问答归 kb-ask。另注意未实现范围：银行、保险、证券专用科目及金融企业指标仍是草案（01/03 号文档标注），摄入金融企业财报前先核对 filing_items.json 覆盖度。

## 1. 定位与职责边界

本 skill 处理已归入 raw/filings/ 的财报（filing 类），产出且仅产出四类客观内容：

1. 科目原值（四表数据行）
2. 派生指标（按指标字典多口径计算）
3. 管理层引述（MD&A、经营讨论、重要事项中的原话，标注语境）
4. 研报目标数据（带目标清单摄入时，按清单补抄的原文数值；见第六步之后的「目标数据补抄」）

以下内容禁止产出：趋势评论、好坏判断、阈值评价、预测、跨期对比的定性描述。同比、单季、TTM 数值本身属于派生指标可以计算，但「增长强劲」「优于同业」之类的表述一律不写。判断类内容归问答 skill（见 .claude/skills/finstmt-qa/SKILL.md）。

## 2. 工作流

代码实现把流程归为四段（定位、抄录、计算、落库），下面七步是同一流程的职能细分。实际调用顺序以 scripts/filing_pipeline.py 的 ingest_filing 为准：定位 → 抄录与归一 → 勾稽 → 管理层引述 → 目标数据 → 派生指标 → 落库，第五步的指标计算在引述与目标数据之后执行。

### 第一步：识别

定位阶段由 LLM 读取每页开头约 80 字（`_locate`），一次提取以下元数据；报告期类型会用截止日月机械校正（03→Q1、06→H1、09→Q3、12→FY），识别不出报告期或公司名时抛错，整份不进入抄录。

1. 公司规范名（落库时按标题、别名、证券代码精确匹配已有公司页，再按 6 位代码匹配，最后按名称包含匹配；匹配不到新建公司页，`_resolve_company_page`）
2. 报告期类型（Q1/H1/Q3/FY）与截止日
3. 报表范围：合并与母公司两套都要抽取，scope 字段区分；母公司科目只进 data/fin 结构化存储，不进 wiki 页面（避免页面膨胀，v1.0 修正）
4. 审计意见类型（标准无保留 / 带强调事项段 / 保留 / 无法表示意见）——客观事实，记入 source 页材料信息
5. 报表格式版本：2018 年及以前的旧格式科目（如「应收票据及应收账款」合并列示）按 02 号文档与 schema/filing_items.json 的别名表归一；归一不了的保留原科目名，listed=false，source 页列入「字典外科目（保留原名）」

### 第二步：定位报表页

定位阶段同时给出主要会计数据页、合并四表、母公司四表、现金流量表补充资料页与 MD&A 页的页码，后续锚点取自这些页。抄录前还会按页内独立成行的「合并/母公司 × 报表名」表头补页（`_ensure_header_pages`），防止报表首页与审计意见同页时整段漏抄；德勤等版式把母公司表头写作「公司资产负债表」时按母公司表算。

### 第三步：抄录与归一

1. 按报表正表逐行抄录，科目名照原文，不改名不翻译；只抄正表行（含「其中：」子项、合计与总计行），附注文字丢弃，只抄数不改数，数值带锚点。抄录按 6 页一批交给模型，解析失败时拆半重抄，单页仍失败向上抛
2. 字典外科目：保留原文科目名，listed=false，不猜测映射；source 页材料信息列入「字典外科目（保留原名）」
3. 缺失科目：跳过，不留空、不估数；核心科目（资产总计、负债合计、所有者权益合计、营业收入、净利润）在合并口径缺失时，先按主要会计数据页补录一次（没有关键页则直接进入挂起判断），仍缺则整份挂起不入库
4. 单位：四表金额行按报表声明的全局单位换算为元。`_detect_unit` 只认资产负债表首页或其上一页的单位声明（含港股「人民幣千元」写法），识别到时覆盖模型逐页填的单位；百分数按百分点原值保留，单位记 %；每股收益保留原值，单位记 元/股；股、件、天等非金额单位保留原值与原单位
5. 原文核对：每行抄录值必须在所标页码原文里核到「科目名 + 数值」（`_value_on_page`），核不到的行丢弃并计数；同名科目按字典报表归属优先、正表优先于主要会计数据，量级差超过 10 倍时保留先入值并打印警告
6. scope 不依赖模型判断：按页内「合并/母公司 × 报表名」标题位置机械覆盖（`_mechanical_scopes`）；同一页排多张表时按标题切分。模型页码写偏、声称页核不到科目名与数值时，先到其他页找真实位置，找不到才退回声称页的表头归属
7. 权益变动表：单独成批且不附带表格文本（pdfplumber 对该表只能抽出无行标的碎列）；报表单位识别成功时，合并权益表关键行（期初未分配利润、未分配利润、提取盈余公积、对所有者或股东的分配）按 token 位置机械取数并覆盖模型抄列（`_eq_fallback`），分配类各行求代数和；提取盈余公积、对所有者或股东的分配若被模型抄成正数，同页原文核到对应负数时翻回负值。标签识别不到的版式（如「上年年末余额 / 本期期末余额」）仍靠模型抄列，已知限制见 docs/待修清单.md 第 61 条

港股年报的列示习惯与 A 股不同，抄录后做两步机械规整：币种从资产负债表首页或其上一页识别（`_detect_currency`），报表若以港元列示，整份不套 A 股四表流程，抛 `UnsupportedFiling` 改走文本编译；以人民币列示的照常入库，但费用与负债总额常写成括号减项，`_fix_statement_signs` 在勾稽前统一翻正（收入为正、成本为负即判定为港股列示）。港股权益变动表口径与 A 股不同，R3 跳过并在日志注明。

### 第四步：勾稽校验

跑 01 号字典 R1—R4 四条规则，容差取 config.ingest.filing_check_tol，当前 0.005，即相对误差 5‰。任一失败：整份报表数值挂起，不入库，失败项逐条打印；不自动修数。部分勾稽依赖的数据缺失（如季报无补充资料）时，对应规则跳过并记录，不影响其余校验。

实现注记（v1.1）：R4 已实现，由 scripts/filing_pipeline.py `_supp_net_profit` 从现金流量表补充资料页机械解析「净利润」行的本期金额，取不到或报表单位未识别时跳过；R1、R2（含期末−期初子校验两条）、R3（容差放宽 5 倍）见 src/fin_calc.py `check_reconciliations`。

实现注记（v1.2）：主要会计数据页缺资产总计、负债合计、所有者权益合计、营业收入、净利润时，自动重抄关键页补录一次，仍缺则整份挂起；同名科目按报表归属优先，现金流量表的存货调整行不会冒充资产负债表存货；同一份财报重摄时，先清掉该报告期由它派生的旧行再并入，避免名称归一或符号修正后留下重复行。

### 第五步：派生计算

1. 按 03 号字典计算派生指标，多口径全算，每条带口径标签
2. 分母或科目缺失的指标跳过，记入缺失清单；按字典规则允许近似的（如 ROIC 利息费用以财务费用近似）打 degraded 标签
3. 报表披露的加权平均 ROE 直接摄取（`ROE(加权披露)`），派生口径并存不覆盖；银行 NIM、不良率、拨备覆盖率等金融企业指标仍是 03 号字典的草案，代码尚未实现（见第 26 行）

### 第六步：管理层引述提取

从定位到的 MD&A 页提取经营情况说明、会计政策变更、业绩指引、风险因素的原话。代码最多扫 20 页、每批 10 页，单批失败跳过；最多保留 8 条，单条截 120 字；context 取值 经营说明 / 业绩指引 / 会计政策 / 风险提示。逐条带锚点。营销性、样板性、免责性文字丢弃。引述是「公司说了什么」的事实，不是本 skill 的观点。

### 目标数据补抄（v1.3，仅带目标清单时）

首页关注点、取数任务与研报管线补定期报告都会带目标清单（研报取的是本次勾选的数据缺口，文档类缺口不进清单）。除四表抄录外，按目标清单再跑一轮：定位阶段会一并返回目标数据出现在哪些页，扫描页取定位页 + 主要会计数据页 + MD&A 页，最多 12 页；单批提取失败跳过，不影响其他批次；结果按 `item`、`scope`、`page`、`value`、`unit` 去重，逐条记 `item`、`scope`（年度与口径）、`value`、`unit`、`page`、`quote`。

- 原文没有的目标不输出，不用相近指标顶替，不估算，不换算单位
- 目标数据不进 `filing_items.json` 科目字典，不参与勾稽；勾稽仍只看四表科目
- 与四表已抄科目同口径同数值的行略过（合并口径、归一后科目名相同、数值差在 0.5% 内），避免同一数字写两遍
- 目标行随公司页「经营与财务」节落库，同时存进 `data/fin/<公司>.json` 的 `periods[报告期].targets`；manifest 中该文件的条目追加 `targets` 列表
- 港股以港元列示的财报仍抛 `UnsupportedFiling` 改走文本编译，目标数据按关注点提炼，不产目标行

### 第七步：落库

公司页「经营与财务」节按固定行格式追加（见第 3 节）；同公司新报告期只增行，同一文件名重摄时先清掉该报告期【数据】【指标】行以及含该文件名的【管理层】行再并入（`_drop_stale_lines`），不同文件名仍并存。source 页按现有规则生成，材料信息含报告期、审计意见、条目数、研报目标数据条数、字典外科目与缺失指标。manifest 记录沿用现有字段，带目标清单时追加 `targets` 列表；抄录、归一、勾稽与指标的中间结果转储到 `data/extracts/<文件名>.filing.json` 供排错。

## 3. 行格式契约（wiki 页内的结构化行）

 wiki 正文一行一条，固定语法，供程序与问答层解析：

- 科目行：【数据】报告期 scope 科目 = 数值元 [[锚点]]
  例：【数据】2026H1 合并 营业收入 = 81,580,000,000 元 [[某某公司2026半年报.pdf#p7]]
- 指标行：【指标】报告期 指标名(口径标签) = 数值 [[锚点]][[锚点]]
  例：【指标】2026H1 ROE(归母平均) = 0.172 [[半年报.pdf#p7]][[半年报.pdf#p60]]
  锚点取该指标取数科目的锚点集合。披露值口径标签写「披露」。
- 目标数据行：【数据】报告期 目标 数据名（口径） = 数值 单位 [[锚点]]
  例：【数据】2025FY 目标 研发投入（2023-2025年） = 50 亿元 [[吉利汽车财报_20251231.pdf#p30]]
  只由带目标清单的摄入产生，数值与单位照原文，不换算
- 引述行：【管理层】「原话」——语境 [[锚点]]
- 缺失记录：不写入页面，只在 source 页材料信息下列缺失指标清单（缺科目或上年数据）；缺失科目由抄录补录与挂起机制处理，不单独列清单

行格式与锚点由 `src/wiki_check.py` 校验：`_line_format_problems` 查等号、数值可解析、口径括号闭合，`content_problems` 查锚点真实与越界；网页写盘前与 Claude 写页钩子共用同一实现。抄录阶段数值不可解析或原文核不到的行由 `scripts/filing_pipeline.py` 丢弃并计数。

## 4. 幂等与重复

同一文件 SHA256 一致跳过（现有机制）。重摄同一文件名的财报会先清掉该报告期由它派生的旧行再并入（`_drop_stale_lines`）；同一报告期不同来源文件（如正式年报与更正版）按文件分别摄取，数据行并存，source 页各自记录，审校阶段人工裁决冲突。
