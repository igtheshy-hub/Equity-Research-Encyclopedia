# 知识库问答

## 1. 选页

- 读 wiki/index.md。问题只关知识库本身（库里有什么、覆盖哪些主题）时直接按索引作答，不带锚点。
- 否则按问题挑相关页，最多 8 页（config.json 的 ask.max_pages），用 Read 读正文。wiki/sources/ 来源摘要页只用来定位材料，不作答依据。

## 2. 作答

- 只用给定页面内容作答，不用模型自身知识补全，与网页问答管道同一口径（src/ask.py）。页面没有的信息明说「知识库中没有该信息」。
- 先给库内支撑的核心回答，再给基于页面内容的归纳；归纳不得引入页面外的事实与数字。
- 库内陈述句尾带锚点 [[文件名.pdf#p页码]]，只原样复用页面中出现过的锚点，禁止新造。句尾没有锚点即视为库外内容，不再标【库外】。
- 含数据的句子，库内数据必须带锚点；外部数据写清来源与日期，两者都没有的按库外估计处理并注明。
- 财报分析类问题按 finstmt-qa 技能纪律：先盘【数据】【指标】【管理层】行再判断，指标带口径与报告期（如 ROE(归母平均)@2025FY），主观判断行以【观点】前缀给出，参考阈值注明出处与适用限度。

## 3. 库里没有时

- 明说「知识库中没有该信息」，不用模型自身知识补答（网页管道同此行为）。
- 用 Glob 搜 raw/ 文件名，把可能相关的材料列给用户；用户确认要核实时读原文（PDF 用 pdf 技能）作答，此时锚点直指 raw 原文，要求文件存在于 raw/ 且页码/块号不越界。

## 4. 新知识沉淀

- 判定：跨页面综合、任何单页都没有明确写出的结论才算新知识；单页已有内容的复述不算。
- 报告成稿后先给正文无锚点句分类：A 综合判断（跨材料、单页没明说）、B 复述漏锚（单份材料已有，补锚点）、C 口径方法、D 前瞻预测、E 推导计算、F 行文框架。A/D/E 三类都进入候选；B 类补锚点或改写成 A 类；C/F 不写入。D 类候选须写明预测条件与日期，E 类候选须经代码复核并挂锚点。
- 把可沉淀的行列出来请用户确认（可只取部分行），每行句尾必须带答案中出现过的锚点，财报判断行用【观点】前缀。
- 报告成稿后的沉淀：A/D/E 三类由主线列成候选，请用户逐条勾选；A/D 类确认后行首用【个人观点】，句尾带支撑它的库内锚点，并括注（个人研报观点，日期，报告文件名），写入行业页或公司页「分析观点」节，D 类句中写明预测条件与日期；E 类按普通数据行写入并注明计算口径。
- 确认后写入：
  - 命中已有页 → 在对应节末尾逐行追加（【观点】【个人观点】行进「分析观点」节，【数据】【指标】行进公司页或行业页「经营与财务」节，其余进「其他」），不动旧行；front matter 的 sources 并入本次锚点文件的 raw 相对路径，updated 改今天，history 追加一行「<日期> 会话中提取（+N 条）」
  - 未命中 → 新建页面，type 决定子目录（company→companies/、industry→industries/、concept→concepts/），front matter 按 schema/CLAUDE.md 模板，history 记「<日期> 会话中提取新建」
  - 节名用 schema/CLAUDE.md 的固定节枚举，没有合适的节用「其他」
- 收尾（索引重建 + 日志）：
  `python -c "from src import wiki; wiki.rebuild_index_md(wiki.load_pages()); wiki.append_log('ask', '<页名>（N 条）：<问题>')"`
- 写入会被 PostToolUse 钩子校验（.claude/hooks/page_check.py），未通过按 stderr 反馈修正后重写。

## 约束

- 合并只追加不删除，锚点集合只增不减。
- 无锚点支撑的内容永不写入 wiki；【观点】【个人观点】行也必须带支撑它的库内锚点。
- manage.py ask 脚本仍可用，但会话内问答一律走本流程。
